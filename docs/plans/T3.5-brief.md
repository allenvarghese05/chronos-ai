## Owner gate

The owner authorised autonomous overnight work on 2026-11-09 ("unless there is a real blocker don't stop"). These decisions were taken under that authority and are open to review:

1. **One durable job per stage.** Jobs are keyed `<stage>:<local_date>:<device_id>`; a forced run adds `:force:<token>`. Each handler enqueues the next stage only after it succeeds. Idempotency comes from the existing unique `(kind, key)` constraint.
2. **`chronos run`** enqueues the chain and drives the real worker until it finishes, with `max_attempts=1` for interactive speed. It ensures the wake-rules version and the `days` row first.
3. **`POST /v1/admin/run`** (bearer auth, 6/min) enqueues for the calling device and returns 202 with the first job.
4. **Prewarm** is due from window start − 30 min until window end. The scheduler collects due chains while processing devices, independent of the push token, and enqueues them after its own commit, so the job queue's transaction never contends with the scheduler's.
5. **`render_mode`.** `eager`: prewarm runs every implemented stage. `on_trigger`: prewarm runs `ingest` only; the remaining stages are enqueued by the scheduler once the day is `confirmed`.
6. **Settings for job processes.** Handlers run in T3.1's minimal environment and cannot read `.env`. The worker writes a settings snapshot into each attempt's private work dir (0600, `O_EXCL`), and the handler deletes it on read. The environment allowlist is unchanged.
7. **Only implemented stages run.** Stages without a handler (assets, tts, captions, render until M4) are skipped with a message.
