# T2.5 — Debug screen implementation plan

## 1. Summary

Provide a protected mobile diagnostics screen with timestamped local/acknowledged signals,
the original stored evaluation, rolling 24-hour scores and explicit tick correlations.
Reuse the singleton wake runtime/outbox for Send now and the existing actual-wake PUT.
Add bounded authenticated read endpoints using existing database tables, no migrations/dependencies.
Preserve staged Simulator acceptance and the outstanding T2.4 physical-device checklist.

## 2. Design

- `GET /v1/debug/wake` returns server UTC/version, explicit current (or requested) day metadata and the latest stored Signals/Evaluation pair. Stored Pydantic models are parsed, never recomputed. If corruption/oversize prevents an honest full response, return a sanitized unavailable error instead of truncating a breakdown.
- `GET /v1/debug/scores` and `/v1/debug/ticks` return at most 40 compact rows each, newest first, opaque bounded cursors and a frozen server UTC interval of exactly 86,400 seconds. SQL normalizes offset timestamps with SQLite `julianday`; stable timestamp/id keysets and an ingestion-time cutoff exclude newly arriving records from existing pages. Client appends pages explicitly and caps loaded data at 400 rows per list, reporting incomplete history.
- Tick attempts retain distinct IDs, date and sequence. Only accepted silent telemetry matching device/date/sequence counts as correlation. Ticket error = send failed; accepted/unmatched age <60 seconds = awaiting; age >=60 seconds = overdue; matching telemetry = received. Receipt status cannot establish execution. No counter subtraction or inferred unsent ticks.
- Three fixed debug GET paths and exact date annotation PUT are added to the method-aware transport allowlist; all retain bearer/lease/TLS/redirect/deadline/32-KiB protections. Runtime response validation rejects malformed remote data. Apply the existing default rate limiter to debug and actual-wake access.
- Telemetry status retains immutable latest-local and acknowledged sample/result pairs, scoped to the active lease generation. The debug controller uses the same native telemetry instance and `wakeRuntime.run('manual')`. Requests coalesce, cancel on blur/background/unmount/session change and never poll sensors. Focus/foreground and explicit refresh fetch server data; controller notifications update local queue state without a fetch storm.
- Annotation accepts exact `HH:MM` for the explicitly displayed server day/timezone. A save is confirmed by readback even after an uncertain PUT error; drafts survive failure, and no annotation changes the score/state. Existing HH:MM DST-fold ambiguity is explained.
- Existing React Native primitives/styles provide textual scores plus a fixed 0–100 bar scale. Empty/partial/stale/unknown values remain explicit. No chart or date-picker package.
- Rejected: parsing Markdown reports (not a contract); using `/day` as 24-hour history (incorrect); a second sampler/controller (race risk); persisting a client history/token cache (unnecessary); relaxing body limits (unsafe).

## 4. Steps

### Step 1 — authenticated bounded server diagnostics

Implement `DebugDay`, `DebugSnapshot`, `ScorePoint`, `TickPoint`, `ScorePage`, `TickPage` Pydantic response models (`extra='forbid'`). Public handlers:

```python
def get_wake_debug(local_date: str | None, device: Device, session: Session) -> DebugSnapshot:
    """Return latest original stored pair and explicit device day metadata; no scoring/I/O outside DB."""
def get_score_history(cursor: str | None, device: Device, session: Session) -> ScorePage:
    """Read a bounded frozen rolling UTC 24-hour page in chronological keyset order."""
def get_tick_history(cursor: str | None, device: Device, session: Session) -> TickPage:
    """Read bounded attempt statuses correlated only to same-device/day/sequence silent telemetry."""
```

Cursor is versioned URL-safe base64 JSON containing aware UTC anchor and last row ID, max512 characters, with valid signed-64-bit ID and permitted anchor age. Reconstruct timestamp from that device's existing row, never trust an arbitrary SQL expression. Every query contains device scope. Scores use normalized `julianday(device_ts)` plus event ID; constrain `received_at <= anchor`, `anchor-24h <= device_ts <= anchor`. Tick pages use normalized `sent_at` plus push ID and the same frozen range. Fetch page-size+1 to produce `next_cursor`; detail rows are projected compactly. Return full snapshot only below30KiB UTF-8; otherwise fixed503 diagnostic unavailable. Never return payload JSON, ticket IDs, token hashes, raw push errors or settings.

Tests: bearer/revoked/other-device protection; empty and persisted latest pair; real original evaluation/derived facts; no scoring mutation; rate limit; byte bounds; two differing-offset DST timestamps ordered by instant; tied timestamps/IDs and page freeze during new insert; full24h exact cutoff; malformed/cross-device/oversize cursors; tick60s boundary/pending/failure/duplicate/manual false correlation/dailyseq reset/late receipt; annotation validation/idempotence/state unchanged.

Verify: `uv run --locked ruff check ...`, `uv run --locked ruff format ...`, `uv run --locked pyright`, targeted `pytest tests/test_debug.py tests/test_day.py`; regenerate via `just gen-types` and run `tests/test_openapi.py`. Passing means all tests and contracts agree; no body cap/schema regression.

### Step 2 — safe typed client and accurate local pairs

Add generated aliases and runtime guards for exact snapshot/page structures, ISO-aware dates, enum values, <=40 rows, bounded IDs/strings/arrays, nested full evaluation and normalized signal bounds. `createApi` gains:

```typescript
debugSnapshot(localDate?: string, budget?: RequestBudget): Promise<DebugSnapshot>;
debugScores(cursor?: string, budget?: RequestBudget): Promise<ScorePage>;
debugTicks(cursor?: string, budget?: RequestBudget): Promise<TickPage>;
actualWake(localDate: string, hhmm: string, budget?: RequestBudget): Promise<void>;
```

Authorization allowlist is method/path-aware; path dates use exact valid calendar YYYY-MM-DD. Annotation validates HH:MM before transport. Parsing its response is unnecessary; existing 32KiB transport cap still applies, and controller readback resolves uncertain results.

`TelemetryStatus` adds `latestLocal: Telemetry | null` and `acknowledged: { sample: Telemetry; result: TelemetryResult } | null`. On enqueue parse/copy the immutable built body; on ACK copy the actual row/result, never pair it with latestLocal. `status()` clears all display fields when owner lease becomes stale and refreshes current count; no credentials enter pairs.

Tests: fixed paths/method/auth header/redirect/32KiB/body cancellation/auth invalidation; malformed nested data, cursors/date input rejection; seq8 queued while seq7 ACK remains paired; external mutation cannot change immutable pair; forget/re-pair clears old pair. Verify both TS projects and focused Jest suites before commit.

### Step 3 — focused debug controller and view

`createDebugController(deps)` exposes `status()`, `subscribe(listener)`, `activate(active)`, `refresh()`, `loadMore(kind)`, `sendNow()`, `setDraft(value)`, `saveActualWake()`, `dispose()`. Inject current lease, telemetry, manual runtime, clock. State contains snapshot, bounded page arrays/cursors/completeness, loaded-at timestamp, busy/error/annotation/draft. Every request captures the current lease, active epoch and abort controller; responses are ignored unless all still match. Deactivation aborts outstanding reads, increments epoch and clears pending flight so reactivation can proceed. Session generations clear data/drafts before exposing a different identity. One read refresh at a time, no timer polling.

Screen exports injectable `DebugView` for fixtures and native `DebugScreen`; protected route mounts it only authenticated. Focus+AppState control activation, cleanup unsubscribes, and outbox updates rerender without native queries. Send now calls the shared manual runtime then refreshes diagnostics. Rows show sequence, capture/receive/source, explicitly queued vs acknowledged, all signals and original breakdown/derived/penalties/notes, elapsed24h bounds, original decisions and fixed0–100 scores, tick status semantics, outbox, versions and existing permission component. Annotation label includes explicit date/timezone and HH:MM limitation; explicit action only.

Tests: fixture renders every requested section and unknown/zero/empty/partial/offline states; action updates after send; immutable sample/result identity; concurrent calls coalesce; blur/background abort; generation switch suppresses late reads/annotation; page caps/frozen anchor; invalidHH:MM/no autosave; successful and timeout-after-commit readback. Verify app/tooling TS, focused Jest and full mobile Jest.
