# T0.6 Plan: Laptop ops

## 1. Summary

When done the owner's MacBook Pro runs the Chronos API as a persistent KeepAlive LaunchAgent
(`com.chronos.api`), automatically deploys from `main` every 10 minutes (`com.chronos.deploy`),
wakes itself at 05:25 weekdays / 07:25 weekends via `pmset`, has a valid mkcert TLS certificate
in `data/certs/` (mode 600), has Kokoro ONNX + whisper + Ollama model files downloaded and
SHA256-verified in `data/models/`, and `chronos doctor` reports the full system health with a
non-zero exit on any blocking failure.

## 2. Design

**Approach:**

- Four shell scripts (`certs.sh`, `models.sh`, `laptop-setup.sh`, `deploy.sh`) plus two plist
  templates rendered into `~/Library/LaunchAgents/` by `laptop-setup.sh`.
- `scripts/models.lock` (committed) stores URLs, SHA256, and sizes for every non-Ollama model file;
  `--pin` mode writes it on first run; subsequent runs verify against it.
- `chronos ops in-deploy-window` is a new Python CLI command that reads `config/wake_rules.yaml`
  (same path as the rest of the app) and computes whether "now" is within the deploy exclusion
  window (window_start − 45 min to window_end). `deploy.sh` calls it as a guard.
- The `chronos doctor` command is fully implemented in Python, using injected callables so tests
  can fake all system probes.
- `scripts/launchd/` contains `.plist.template` files; `laptop-setup.sh` renders `REPO_ROOT` and
  `UID` into them via `sed` before installing.
- Two sudo steps (`mkcert -install`, `pmset repeat`) prompt interactively when stdin is a TTY and
  print a "RUN THIS" banner otherwise (scripts detect with `[ -t 0 ]`).

**Rejected alternatives:**
- Hardcoded SHA256 in `models.sh` (no `--pin`): inflexible when upstream releases update.
- A single plist file without templates: hard to embed the repo root at install time.
- Reading deploy window from a hardcoded constant: owner answer 6 requires reading from the YAML.
- `osascript` for sudo prompts: adds macOS-only complexity; print-command is simpler and safer.

**Complete implementation:**

```python
# services/api/src/chronos/ops/deploy_window.py
"""Deploy-window guard: pure function for T0.6.

The deploy exclusion window is:
    [window_start - LEAD_MIN, window_end)
where LEAD_MIN = 45 and times are in the phone's/server's local timezone.

Called by ``chronos ops in-deploy-window`` and by scripts/deploy.sh (via the CLI).
"""
from __future__ import annotations

import datetime
from zoneinfo import ZoneInfo

from chronos.wake.rules import WakeRules
from chronos.wake.window import day_kind, window_for

LEAD_MIN: int = 45


def in_deploy_window(
    now: datetime.datetime,
    rules: WakeRules,
    tz: ZoneInfo | None = None,
) -> bool:
    """Return True if *now* falls inside the deploy exclusion window.

    Args:
        now: A tz-aware UTC datetime.
        rules: The active WakeRules (read from wake_rules.yaml).
        tz: Local timezone; defaults to ``ZoneInfo("America/Los_Angeles")``.

    Exclusion window = [window_start − LEAD_MIN, window_end).
    Both endpoints are in local wall-clock time on the same local date as *now*.
    """
    if now.tzinfo is None:
        raise ValueError("now must be tz-aware")
    local_tz = tz or ZoneInfo("America/Los_Angeles")
    local_dt = now.astimezone(local_tz)
    local_date = local_dt.date()

    wc = rules.window.to_window_config()
    kind = day_kind(local_date, wc)
    win = window_for(local_date, wc, kind)

    # window_start and window_end are naive times → combine with local_date
    excl_start = datetime.datetime.combine(local_date, win.start, tzinfo=local_tz) - datetime.timedelta(minutes=LEAD_MIN)
    excl_end = datetime.datetime.combine(local_date, win.end, tzinfo=local_tz)

    return excl_start <= local_dt < excl_end
```

**Tests (`test_deploy_window.py`):**
- `test_weekday_inside_lead` — 10 min before window start → True
- `test_weekday_at_window_start_minus_lead` — exactly at boundary → True
- `test_weekday_before_exclusion` — 50 min before window start → False
- `test_weekday_after_window_end` — 1 min after end → False
- `test_weekend_inside` — weekend mid-window → True
- `test_weekend_outside` — weekend before lead → False
- `test_naive_now_raises` — ValueError

### Step 4 — `scripts/certs.sh`

**Files touched:** `scripts/certs.sh`

**Logic (idempotent):**
1. Check `mkcert` installed; error if not.
2. Detect `CAROOT=$(mkcert -CAROOT)`.
3. If `$CAROOT/rootCA.pem` doesn't exist: check if running interactively, run `mkcert -install`
   (prompts for sudo) or print "RUN THIS" banner.
4. Skip cert generation if `data/certs/chronos-lan.pem` exists and is not expired within 7 days.
5. Create `data/certs/` directory.
6. Detect hostname via `scutil --get LocalHostName` → `<name>.local`.
7. Detect LAN IP via `ipconfig getifaddr en0` (fallback env var `CHRONOS_LAN_IP`).
8. Run `mkcert -cert-file data/certs/chronos-lan.pem -key-file data/certs/chronos-lan-key.pem <hostname>.local <LAN_IP> localhost 127.0.0.1`.
9. `chmod 600 data/certs/chronos-lan-key.pem data/certs/chronos-lan.pem`.
10. Copy rootCA to `data/certs/rootCA.pem` (`chmod 600`).
11. Print cert expiry + iPhone profile installation instructions (AirDrop or `python3 -m http.server`).


### Step 6 — `scripts/models.sh` + `scripts/models.lock`

**Files touched:** `scripts/models.sh`, `scripts/models.lock`

**Logic:**
- Read `OLLAMA_MODEL=$1`, `OLLAMA_DIGEST=$2` from args.
- Accept `--pin` flag: download first, compute SHA256, write lock file, then verify.
- For each model (Kokoro onnx, Kokoro voices, whisper):
  - Skip if file exists and SHA256 matches lock.
  - `curl -fL --retry 3 --continue-at - -o <tmp>` (resumable).
  - Verify SHA256; on mismatch delete tmp and exit 1.
  - `mv tmp → final path`.
- `ollama pull $OLLAMA_MODEL` (Ollama handles its own digest).
- Read digest: `ollama show --json "$OLLAMA_MODEL" | python3 -c "import json,sys; d=json.load(sys.stdin); print(d.get('details',{}).get('parent_model','') or d.get('modelinfo',{}).get('general.basename',''))"` — actually use `ollama list` and parse.
  - Print: `"Set ollama_digest in justfile: sha256:..."`.
  - Compare to `$OLLAMA_DIGEST` if non-empty; warn if mismatch.
- `cd packages/renderer && pnpm exec remotion browser ensure` (if renderer exists).

### Step 7 — `scripts/deploy.sh`

**Files touched:** `scripts/deploy.sh`

**Logic:**
1. `REPO_ROOT=$(cd "$(dirname "$0")/.." && pwd)` — detect from script location.
2. `source .env` (from repo root `services/api/.env`).
3. `LOG=data/logs/deploy.jsonl`.
4. Define `log_json()` helper: writes `{"ts":"...","sha":"...","status":"...","msg":"..."}`.
5. `git fetch origin main --quiet`.
6. `PREV=$(git rev-parse HEAD)`.
7. If `$(git rev-parse HEAD) == $(git rev-parse origin/main)` → log `status=up-to-date` exit 0.
8. **Deploy-window guard**: `uv run --locked chronos ops in-deploy-window`; exit code 0 = in window; exit 1 = not. If in window → log `status=skipped` exit 0.
9. `git verify-commit origin/main 2>/dev/null || echo "WARNING: commit signing not configured; skipping verify"`.
10. `git merge --ff-only origin/main || { log_json failed "ff-only merge failed"; exit 1; }`.
11. `(cd services/api && uv sync --locked)`.
12. `[ -d packages/renderer ] && (cd packages/renderer && pnpm install --frozen-lockfile)`.
13. `(cd services/api && uv run --locked chronos db migrate)`.
14. `(cd services/api && uv run --locked chronos config validate)`.
15. `launchctl kickstart -k gui/$UID/com.chronos.api`.
16. Health check with retries: `curl -fsS --cacert data/certs/rootCA.pem https://<host>:<port>/readyz`.
17. On failure: `git reset --hard "$PREV"` + kickstart + log `status=rolled-back`.
18. On success: log `status=ok`.
19. `--dry-run` flag: print each action without executing; exit 0 always.
20. Lockfile: `flock data/deploy.lock` (prevents race conditions if launchd overlaps).

## 8. Review focus

1. **`deploy.sh` rollback** (step 7, lines handling `git reset --hard`): must never corrupt a
   working tree that has local changes (it doesn't — we enforce ff-only, so local commits cause
   early exit before any merge).
2. **`in_deploy_window` edge cases** (`test_deploy_window.py`): DST boundary, midnight-crossing
   window math.
3. **`doctor` probe injection** (`test_doctor.py`): ensure no subprocess is ever called in tests.
4. **plist template rendering** (step 5, `laptop-setup.sh` sed invocations): `__REPO_ROOT__`
   contains `/` so `sed -i '' "s|__REPO_ROOT__|$REPO_ROOT|g"` must use `|` as delimiter.
5. **`certs.sh` mode 600** (step 4): applied after every generation, including regeneration.
