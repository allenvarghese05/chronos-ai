# T3.1 — Durable queue implementation plan

## 1. Summary

Add the five content/job tables and migration 0003, a durable fenced SQLite queue, a serial
worker and a single safe process execution boundary. A host execution lock remains held by
the supervisor/handler descendants until cleanup is proved, even after API worker death.
Expose only bounded authenticated job metadata. No live pipeline handlers are registered.

## 2. Design

- SQLModel plain foreign keys, shared string enums and named CHECK/unique/index constraints
  mirror migration 0003, whose parent is the applied revision `08a434829bca`.
- Content fields follow `docs/04`; unsigned simhash conversion uses reversible two's-complement
  signed INTEGER storage. Draft script storage is not semantic ReelScript validation.
- `JobQueue` owns an engine, never a shared Session. Each enqueue, claim and fenced update uses
  a short independent transaction. Queue instants must be aware; persisted ISO timestamps are UTC.
- The canonical configured data directory holds one non-unlinked `jobs/execution.lock`, shared
  by every database on this single-user host data root. Workers acquire its nonblocking flock
  before reclaim/claim. Symlink aliases resolve to one root; lock-file symlinks are refused.
- The worker passes the same open-file-description lock FD to an ephemeral Python supervisor.
  Closing a worker FD never explicitly unlocks the shared lock. A liveness pipe closes on API
  crash. The supervisor runs a trusted importable Python handler in its own process group,
  monitors deadline/liveness, escalates TERM to KILL, and reaps before emitting a safe result.
  Handler tools use the single wrapper, inherit execution ownership and remain in the attempt
  group. Detached/untrusted children are outside the supported handler contract.
- If cleanup cannot be established, the supervisor retains ownership and the worker stops
  claiming. No retry occurs merely because a DB lease elapsed. This is at-least-once recovery,
  not exactly-once publication of arbitrary external effects.
- macOS sleep assertion is a managed `/usr/bin/caffeinate -i -w <supervisor-pid>` process;
  failure to start is an execution failure. Linux uses no assertion. Both paths have test seams.
- Worker orchestration runs in one stoppable background thread; the handler is killable, not
  a cancelled thread. No DB writer transaction spans work. Registry is internal and empty in
  production until future tasks add real stages; unsupported queued kinds remain untouched.
- Worker defaults enabled outside `env=test`, with explicit `CHRONOS_WORKER_ENABLED=false` and
  `chronos serve --no-worker` controls independent of scheduler. Existing tests opt out.
- GET jobs projects IDs/enums/counts/times/safe outcome codes, omitting key, payload, lock owner,
  traceback, process output and paths. ID-keyset pagination is bounded to 40 rows/30 KiB.

Rejected: Redis/Celery (new service/dependencies); per-row locks alone (different jobs overlap);
lease expiry alone (does not stop work); cancelling a thread (cannot kill Python/descendants);
running work inside a SQLite transaction (blocks telemetry); HTTP argv/enqueue (untrusted execution).

## 4. Steps

### Step 1 — schema and migration

Implement the complete documented content fields, defaults and plain composite FK from briefs
to days. Jobs default attempts=0/max_attempts=3; bounds: priority -100..100, attempts 0..10,
max_attempts 1..10, timeout 1..3600 seconds, key 1..200 UTF-8 chars, payload JSON object <=16 KiB.
CHECKs enforce statuses/kinds/nonnegative counters/booleans and counts. `title_simhash` stores
signed64; `encode_simhash(value: int) -> int` accepts unsigned64 and `decode_simhash(value: int)
-> int` accepts signed64. Defaults do not claim content is ready or validated.

Generate migration with Alembic against an isolated prior-head DB; review every FK/index/check
and downgrade reverse dependency order. Extend existing head table expectation without weakening
parity or drift checks. Tests: populated previous-head rows survive upgrade and downgrade;
base roundtrip; exactly five new tables; invalid FK/status/duplicate IDs fail; high-bit simhash
roundtrips; compare_metadata remains empty.

Verify: `uv run --locked pytest tests/test_migrations.py tests/test_migration_0002.py
tests/test_migration_0003.py tests/test_schema_constraints.py`; `ruff check/format`; `pyright`.
Commit after all pass.

### Step 2 — durable queue

Public internal interfaces:

- `JobInput` strict Pydantic model: kind, key, JSON-object payload, priority=10,
  max_attempts=3, timeout_sec by kind. Reject nonfinite/nested-overdeep/oversized data.
- `Claim` frozen dataclass: id, kind, immutable payload JSON, attempts, timeout_sec, owner token.
- `JobQueue(engine: Engine)`; `enqueue(input: JobInput, now: datetime,
  run_after: datetime | None = None) -> Job`: atomic INSERT ON CONFLICT DO NOTHING then read;
  the original row always wins without silently replacing its body or status.
- `claim(kinds: set[JobKind], now: datetime) -> Claim | None`: UPDATE candidate due queued
  row ordered priority/id, status compare, fresh random ownership and attempts+1, RETURNING row.
- `complete(claim: Claim, now: datetime, duration_ms: int) -> bool` and
  `fail(claim, now, duration_ms, reason, cancelled=False) -> bool`: UPDATE only matching
  id/status running/locked_by. Safe fixed error codes; no raw exception text.
- `reclaim(now: datetime) -> int`: caller must hold execution ownership and know no previous
  attempt exists; reclaim expired running rows with owner CAS. Retry delay is
  `min(300, 5 * 2 ** (attempts - 1))`; exhaustion becomes failed with finish timestamp.

Every mutation commits internally; no Session crosses threads. Canonical timestamps use
`format_utc_iso` after rejecting naive instants. Claim skips unknown kinds without consuming
attempts. Backoff, source payload and original key remain stable.

Tests: independent connections claim once; concurrent duplicate enqueue returns one original;
priority/due/unknown kind selection; aware-offset normalization/naive rejection; A cannot complete,
fail or release B; three failures exhaust with fixed-clock run_after; malformed payload/bounds.
Verify `uv run --locked pytest tests/jobs/test_queue.py`; ruff and pyright; commit.

### Step 3 — execution lock, supervisor and worker

Interfaces:

- `ExecutionLock(data_root: Path)` with nonblocking `acquire() -> bool`, `fd`, `close()`.
  O_NOFOLLOW + regular-file/inode checks, mode0600, canonical root; never unlink or explicitly
  unlock an FD shared with execution descendants.
- `ProcessResult` frozen bounded bytes/return code/duration; `run(argv: list[str], *,
  timeout: float, cwd: Path, data_root: Path, env: Mapping[str,str] | None = None,
  cancel: threading.Event | None = None, output_limit: int = 65536) -> ProcessResult`.
  Resolve cwd under root, validate finite budget/argv; fixed minimal environment plus allowlisted
  caller keys. Drain both pipes continuously, keep at most output_limit each. On deadline/stop,
  TERM/KILL the owned group and reap. A supervised handler's timeout stops its whole attempt.
- `Handler` trusted importable module+function registration, not serialized executable payload.
  `JobContext` frozen job/owner/payload/workdir/root object for future handlers.
- `run_handler(handler, context, *, lock_fd, cancel, timeout) -> ExecutionOutcome` starts the
  internal supervisor through the same process module; lock/liveness descriptors are explicit.
  Request lives mode0600 under generated numeric/token workdir, never a key-derived path.
- Supervisor loads only the trusted parent-supplied handler identity, forks the handler after
  fresh-interpreter startup, and monitors its process group, parent pipe and monotonic deadline.
  Parent death/stop/deadline => TERM, short grace, KILL, reap group, safe result. Linux subreaper
  support may be used through stdlib ctypes to reap adopted descendants; macOS launchd reaps
  orphan descendants. Uncertain cleanup retains flock and fails closed rather than admitting work.
- `Worker(queue, data_root, handlers, clock, poll_interval)`; `run_once(stop) -> bool` acquires
  OS ownership before reclaim/claim; runs one attempt; fenced final update only after safe cleanup;
  closes parent FD; `run_forever(stop)` waits on stop rather than uninterruptible sleeping.

Tests use real independent processes and shared interval files: different jobs never overlap;
worker SIGKILL while child lives prevents second claim until supervisor cleanup; genuine Python
sleep timeout and TERM-ignoring tool descendant terminate; stale completion rejected; stop cleans
group; reader DB transaction proceeds during work; symlink/env/output flood/caffeinate tests.
Verify `uv run --locked pytest tests/jobs/test_execution.py tests/jobs/test_worker.py` plus
queue regression/types/lint; commit only after actual process tests pass.

### Step 4 — app lifecycle, read API, documentation and full verification

Add `worker_enabled: bool | None = None` (effective enabled except test unless explicitly set),
`data_root: Path` default repository `data/`, worker poll0.25s/stop budget5s bounds. CLI
`--no-worker` sets only CHRONOS_WORKER_ENABLED=false. Worker registry is empty by default.
Lifespan starts a thread with its own queue/session factory, stops it and reaps before engine
disposal; startup failure still closes clients/engine. Thread waits are awaited off event loop.
All existing tests explicitly disable worker; opt-in lifecycle tests inject handlers.

GET `/v1/jobs?status=&limit=&cursor=`: default40/max40, positive ID cursor, reverse ID keyset,
safe status enum and `JobPage(jobs, next_cursor)`. JobSummary includes id/kind/status/priority,
attempts/max_attempts, run_after/start/finish/create times, timeout/duration and allowlisted
outcome; never key/payload/raw error/lock/path. Validate a serialized response <=30 KiB.
Existing bearer auth/default120 rate limit and RFC9457 errors apply. No mutation endpoint.

Tests: auth/revocation/filter/cursor/limits/leak canaries; worker enabled/disabled/independent
scheduler/shutdown/startup-failure/engine-order and responsive API while job runs; no default
handlers/automatic enqueue. Regenerate contracts; exact fixture export matches. Update docs
with lock/recovery/handler and no-exactly-once contract, enable/disable controls and pending
downstream stages. Run `just check` and `just security`, fix only task-caused failures, commit.

## 5. Dependencies

None. Standard-library POSIX process/locking/selectors/ctypes facilities and existing pinned
SQLModel/SQLAlchemy/Pydantic/Alembic suffice. No dependency/audit policy changes are authorized.

## 6. Acceptance check

| Criterion | Proof |
|---|---|
| Migration up/down | Step1 fresh/populated/roundtrip/parity/constraints tests |
| Two workers never run same job | Step2 real connection race + Step3 process lock/interval tests |
| Failed jobs back off then fail | Step2 fixed UTC retry/exhaustion + Step3 handler failure |
| Timeout kills sleeping job | Step3 actual Python sleeper and TERM-ignoring descendants |
| Safe different-job seriality/crash recovery | Step3 two-process interval + killed-worker tests |
| Bounded authenticated jobs listing | Step4 API bounds/filter/auth/leak tests |
| Existing system preserved | Full checks/security, no live owner DB or service mutations |

## 7. Out of scope

Live feed fetching, source YAML loading, ranking, LLM/ReelScript generation, media/reels tables,
pipeline chaining, automatic enqueue, HTTP enqueue/admin-run, mobile jobs UI, retention deletion,
Apple/Expo provisioning, unrelated wake scoring/settings/native changes, Redis/Celery, distributed
workers and exactly-once external effects. Existing acceptance services/data remain untouched.

## 8. Review focus

1. Lock-FD lifetime across parent crash, supervisor cleanup and handler tool descendants.
2. Atomic claims and ownership CAS on every terminal/retry/reclaim operation.
3. Group termination/output drain/minimal environment/cwd symlink boundaries.
4. Migration composite FKs/check/index parity and existing data preservation.
5. Lifespan shutdown ordering, test opt-out and safe metadata-only API projection.
