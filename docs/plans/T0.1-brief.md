## Why it matters

T0.1 establishes the foundation for all subsequent work. It provides:
- A single task runner (`just`) with skip-on-missing semantics so every task can begin with `just check` passing before any scaffolding
- Pre-commit hooks that enforce linting, formatting, security checks and secret scanning locally
- CI workflows that enforce the same checks on every PR
- Documentation (design docs, decisions, task plan, open questions) that guides implementation
- Project agents (understander, implementer, reviewer, pusher) with fixed prompts and models
- Security controls (secrets gitignore, `.env.example` docs, gitleaks, semgrep config) to prevent accidental commits of credentials and known vulnerabilities
- Repo layout (monorepo with `apps/mobile`, `services/api`, `packages/renderer`, `scripts/`, `docs/`, `data/` gitignored) that scales through M6

Without this scaffolding, subsequent tasks cannot initialize their projects, run CI, or enforce quality. If any file is incomplete, later tasks will either fail at the start or skip checks they should enforce.

## Edge cases

1. **First run on a fresh machine (no uv, pnpm, git installed)**
   - `just setup` fails with a message to install uv first
   - Expected: developer installs uv from https://docs.astral.sh/uv/ and retries
   - Test: `rm -rf ~/.local/share/python* ~/.cache/uv 2>/dev/null; just setup` on a CI runner that has uv pre-installed

2. **`just check` run before apps are scaffolded**
   - All recipes see `services/api/pyproject.toml` missing and print "skipping lint" for that app
   - Expected: composite `check` recipe prints "all steps passed (apps not yet scaffolded were skipped)" and exits 0
   - Test: runs in every CI check job; confirmed by current repo state

3. **Pre-commit hook runs on files in `services/api/tests/fixtures/` (golden files)**
   - The `exclude:` pattern in `.pre-commit-config.yaml` skips `services/api/tests/fixtures/`, `packages/renderer/src/fixtures/`, and `data/`
   - Expected: golden files are never reformatted or linted by the hooks, only checked for secrets
   - Test: commit a `.json` file to `services/api/tests/fixtures/`; it should not trigger biome or ruff

4. **Gitleaks runs on staged changes only (pre-commit) vs. full history (CI)**
   - Pre-commit hook uses `pass_filenames: false` and `always_run: true`, so it checks only staged content
   - CI job `secrets` (in `ci.yml`) runs `gitleaks detect --source github --repo-config-path .` (full history)
   - Expected: CI catches secrets that were nearly committed but pre-commit missed (e.g., in CI workflow file that was not linted)
   - Test: add a fake secret to a file, don't stage it, run pre-commit; gitleaks should not block. Then add it to a workflow file, stage it, run pre-commit; gitleaks should block.

5. **CI workflow file changes must pass actionlint**
   - Pre-commit hook `actionlint` lints `.github/workflows/*.yaml` files
   - Expected: a malformed GitHub Actions workflow is caught locally before push
   - Test: break a workflow file's syntax, run pre-commit; actionlint should fail

6. **`just security` called on a machine without internet (offline network)**
   - semgrep and pnpm audit need to fetch rulesets/advisories from the internet
   - gitleaks, pip-audit can run offline (they check local files)
   - Expected: semgrep and pnpm audit report "registry unreachable, skipping"; bandit and gitleaks pass or report their findings
   - Test: block internet access, run `just security`; observe graceful skip messages

7. **User upgrades Node and edits `.nvmrc` without testing Expo**
   - Expected: CI job `mobile` runs on ubuntu-latest which uses the .nvmrc version; if the version is broken, the job fails and the PR is blocked
   - Test: change `.nvmrc` to `99.99.99`, push to a PR branch; CI mobile job should fail

8. **Pre-commit modifies a file auto-fix (ruff, biome) but developer does not stage the new version**
   - ruff and biome have auto-fix enabled; a commit with violations will pass the hook (auto-fixed), but the working directory is dirty
   - Expected: developer must `git add` the fixed file and recommit
   - Test: violate a ruff rule (e.g., trailing whitespace), run pre-commit; ruff fixes it, hook exits 0; run `git status` to see the file is modified; run pre-commit again; it passes because the working tree is now clean

## Risks

| Risk | Likelihood | Mitigation | Test |
|---|---|---|---|
| `just` recipe has a typo that breaks `just check` on CI | Low | recipes tested locally before commit; CI runs them first | `just check` and `just check-{api,mobile,renderer}` pass on every CI run |
| A pre-commit hook fails unexpectedly when a new app is scaffolded | Low | hooks use `if [ -f <path> ];` guards; wrappers handle missing apps | Scaffold T0.3 and run `just check`; pre-commit should still pass |
| GitHub Actions SHA pins become stale or point to wrong commits | Low | Dependabot updates them weekly; zizmor lints workflows | Weekly CI audit job; manual `gh workflow view` on any updated workflow |
| Private repo cannot enforce ruleset, leaving main unprotected | Medium (by design) | agents' never-push-to-main rule; agent scope enforces branch review | PR-only workflow in CI (PRs run all checks before merge); agents can open but never merge |
| Secrets slip through pre-commit gitleaks | Medium | gitleaks has growing signature database; pre-commit only checks staged content; CI checks full history | Periodic `just security` runs; CI blocks PRs if secrets are found |
| Tool versions in justfile and CI diverge | Low | CI hardcodes the version from the justfile (e.g., `$(just --evaluate semgrep_version)`) | CI job `api` checks that installed semgrep matches the pin |
| Gitignore misses data files and they get committed | Low | pre-commit `no-data-dir` hook explicitly blocks data/*, *.pem, *.p8, .env | Add data/test.db to staging; pre-commit should fail with "refusing to commit" |
