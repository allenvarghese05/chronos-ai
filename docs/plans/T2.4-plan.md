# T2.4 — Background wake handling implementation plan

## Summary

Connect silent push, native background refresh and actual foreground transitions to the secure persistent sampler/outbox. Define the headless task before Router and restore credentials without an extra background validation request. Preserve per-execution native completion and one bounded app runtime. Show actual permission statuses and honest iOS limitations. This is staged Simulator implementation: full T2.4 device acceptance remains pending.

## Design

- Global `index.ts` imports wake bootstrap before Router. TaskManager definition is unconditional; notification registration/import is gated to physical iOS with an existing project UUID. Registering a task never prompts for permission.
- One telemetry controller per session owner, shared by manual and automatic paths. New per-attempt outcomes distinguish acknowledged, queued, skipped and failed; overlapping calls report skipped rather than borrow another source's outcome.
- A background attempt has an 18-second absolute monotonic deadline, including secure restore. Abort guards prevent late work enqueueing or acknowledging after expiry. Sensors retain five-second budget; flush retains eight-second cap and respects the outer abort/deadline.
- Session `restore()` memoizes local Keychain hydration only; `hydrate()` preserves foreground validation. Background callbacks never request permissions or select credentials/origin from payload.
- Decode native normalized notification envelopes (bounded `dataString` or data object), reject visible/actions/non-ticks and invalid sequence/date/context. Context is in-memory, bound to current paired identity/timezone/day. Server owns scoring/window rules.
- Native launch-owned singleton holds one refresh execution with UUID, completion closure, expiration and 25-second timer even before module/JS readiness. An explicit pending claim after listener installation closes replay races; IDs reject stale completions. A pure Swift coordinator owns testable state transitions. Generated Expo AppDelegate starts React Native unconditionally in didFinishLaunching; the subscriber does not invent an unsupported secondary bridge.
- Foreground subscription is global and identity/transition-aware, avoiding React StrictMode/remount duplication. Background → inactive → active counts once; repeated active events do not. Pairing while active samples once.
- Paired permission controls read Motion and native Background App Refresh statuses, gate notifications imports, and prompt only on explicit foreground actions. No automatic prompt on launch.
- Correct scheduler silent ticks to normal priority without changing generic visible-message priority or cadence.
- Rejected: React-effect headless setup (too late); transient-only native events (lost cold-start work); success in `.finally` (false success); Simulator push tokens or unsigned builds (invalid evidence); EAS provisioning (owner lacks membership); guessed client wake windows (server authority).

## Steps

### 1. Secure bounded telemetry primitives

Public interfaces:

- `SessionController.restore(): Promise<void>` reads only the saved secure record; existing `hydrate(): Promise<void>` additionally validates. Both share the same local restore. Retry hydration resets local restore as before. A stale generation cannot publish a restored session.
- `WakeAttempt = { signal?: AbortSignal; deadline?: number; tickSeq?: number }` uses monotonic milliseconds. `TelemetryOutcome = 'sent' | 'queued' | 'skipped' | 'failed'` describes only this invocation.
- `sampleAndSend(source: WakeSource, context?: WindowContext, attempt?: WakeAttempt): Promise<TelemetryOutcome>` checks cancellation/current lease before sampling, before enqueue and after flush. Concurrent sampling returns skipped. `flush(attempt?: WakeAttempt): Promise<TelemetryOutcome>` returns sent only after an actual current-lease ACK, queued when original rows remain, failed on storage/auth/deadline failure and skipped for no work. An outer abort cancels transport; timer/listener cleanup always runs.
- Native sample adapter receives optional tick sequence and calls existing `sample(..., context, tickSeq)`. Cache controllers in a WeakMap keyed by session controller; preserve the one private outbox connection.

Tests: local restore sends no GET; hydrate still validates; lost ACK/immutable FIFO existing regressions; expired/stalled sampling never enqueues; per-call outcomes cannot reuse stale lastResult; concurrent source skips; tick sequence preserved; outer abort bounds body reads. Verify `pnpm exec jest --ci --runInBand __tests__/session-store.test.ts __tests__/telemetry-controller.test.ts` and mobile typecheck; all pass.

### 2. Pure wake parsing and runtime

`parseTick(envelope: unknown): Tick | null` accepts the installed native envelope only. `Tick = { tickSeq: number; localDate: string; windowStart: string }`. Object checks exclude arrays/null; reject actionIdentifier/visible aps alert/sound/badge; dataString maximum 4096 characters before JSON.parse; tick_seq safe integer >=0; local_date strict YYYY-MM-DD with calendar validity; window_start bounded offset ISO timestamp and parseable. Whitelist returned fields, never pass URL/token values into transport. Existing sampler validates context against actual timezone and timestamp; malformed/stale context cannot invent window queries.

`createWakeRuntime(deps)` exposes `run(source, tick?, externalAbort?): Promise<TelemetryOutcome>` and `foreground(active:boolean): void`. Dependencies provide session restore/lease, telemetry getter, actual metadata, clock, elapsed clock and refresh scheduler. One 18-second abort/deadline includes local restore, sensor and flush; raced late restore completion does not start expired work. Cache context only for the current identity and actual timezone/day; invalid/old context falls back to zero-window behavior. Each real active transition or newly paired identity triggers one foreground sample. No dependency on React mounting.

Tests: native object/dataString fixtures; visible/action/non-tick/oversized/malformed inputs; denied motion remains actual enum; stalled restore returns failed without native work; late callbacks cannot enqueue; genuine transitions and new pairing sample once; duplicate active/remount doesn't sample; identity changes discard context; concurrent wake doesn't mislabel outcome. Verify focused Jest suites and typecheck, all pass.

### 3. Native refresh ownership

`RefreshCoordinator` is pure Swift and main-actor owned: `begin(id:completion:)`, `claim() -> String?`, `finish(id:success:)`. Begin fails an older pending execution once; claim delivers once; finish acts only on matching UUID and clears state before invoking completion. This is the complete transition algorithm (no persistence of task handles or credentials).

Launch-owned native manager creates UUID/timer and expiration before posting an availability notification. Module listener emits availability after installation; `takePendingBackgroundRefresh(): { id: string; executionId: string } | null` atomically claims pending work. `completeBackgroundRefresh(executionId: string, success: boolean): void` only completes that execution. `backgroundRefreshStatus(): 'available'|'denied'|'restricted'|'unknown'` reads UIKit on main. Schedule validates exact identifier/finite positive delay, replaces existing request instead of accumulating requests, returns boolean success. Notification/listener readiness never claims task before JS can handle it. Timer/expiration/completion identity guards cancel timer and call native completion once. Native completion emits endedExecutionId; bootstrap aborts only that execution’s linked runtime signal, preventing expired native work from enqueueing or acknowledging late sensor/transport results. Native timer exists without JS/module initialization. The generated AppDelegate starts React Native at launch; cold-launch device execution still requires acceptance evidence.

Tests: pending before readiness, one claim, no-JS expiry, A expires/B begins/A completion, replacement and reentrant completion. Verify `just mobile-ios-test`; all Swift tests pass. Also verify TS signatures in module/fallback tests.

### 4. Global entry and permissions

Add exact `expo-task-manager@57.0.21`. Entry imports bootstrap before `expo-router/entry`; define task at module scope using actual SDK result enum values without importing side-effectful notifications on Simulator. Actual enum mapping is NewData=0 / NoData=1 / Failed=2 and is source-guarded in tests. Gated notifications load and registerTaskAsync execute only with physical supported config, without requesting permission. Native listener first then takePending claim closes prelistener gap. Schedule after attempts; errors are bounded status, no logging payload/secrets. Global AppState/store subscriptions drive runtime once and do not depend on provider remounts.

Permission component reads actual Motion/refresh/device status and separately notification permission when supported. Explicit foreground buttons request Motion or call existing registerPush; background code never calls either. Show force-quit, first-unlock, low-power and opportunistic refresh caveats, plus distinct Simulator/missing project status. Settings link opens iOS Settings. Legacy Home step query checks authorization first so rendering never triggers a permission prompt. Preserve manual telemetry controls.

Tests: TaskManager defined before Router, gated notification side effects, real SDK envelope/result mapping; pending native event claimed after listener, scoped completion on every path; permission enum/status text and no automatic prompt; settings action; home authorization guard. Verify focused/full Jest, typecheck, `just check-mobile`, normally signed Simulator build. No physical acceptance claim from these results.
