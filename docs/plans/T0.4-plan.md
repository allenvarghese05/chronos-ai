# T0.4 Plan: Mobile scaffold `apps/mobile`

## 1. Summary

Creates `apps/mobile` — a fully configured Expo SDK 57 project with TypeScript strict mode, Biome
linting, jest-expo tests, and the `modules/chronos-sensors` local Swift Expo Module. The root
screen displays `hello()` from the native module. `just check-mobile` passes locally and in CI
(ubuntu-latest, no Xcode). The `ios/` and `android/` native directories are git-ignored; the
device-install step is split into follow-up task T0.4b. The implementation plan and README record
every pinned version. `docs/11-implementation-plan.md` gains a T0.4b row.

## 2. Design

**Approach:** all files are created manually rather than running `create-expo-app` interactively,
because the interactive prompt cannot be automated and the resulting tree would need heavy cleanup
(remove Android templates, add Biome, add tests, etc.). The `expo-module.config.json` and Swift
skeleton follow the same structure that `npx create-expo-module --local chronos-sensors` would
produce; Android and web artefacts are omitted per D01 (iOS only).

**pnpm 12.x + Metro requires `nodeLinker: hoisted` in `pnpm-workspace.yaml`:** Metro (React Native's
bundler) does not understand pnpm's default symlink-based node_modules layout. In pnpm 12.x,
project settings like `nodeLinker` moved from `.npmrc` to `pnpm-workspace.yaml`. Setting
`nodeLinker: hoisted` in `apps/mobile/pnpm-workspace.yaml` makes pnpm produce a flat node_modules
tree that Metro can traverse, and also ensures `expo-modules-core` (a transitive dependency of
`expo`) is hoisted to the top-level node_modules so TypeScript and the local `chronos-sensors`
module can resolve it without listing it as a direct dependency (which expo-doctor rejects).
Documented here so the reviewer can find the rationale.

**Plugins:** `expo-notifications`, `expo-secure-store`, and `expo-video` are listed in
`app.config.ts` plugins (per docs/08-mobile-app.md §1) so their native config is registered now;
they are installed as runtime dependencies so the plugin resolution does not fail during
`expo export`. Their JS APIs will be wired in T2.x.

**Alternatives rejected:**
- `create-expo-app --template blank-typescript` — interactive, cannot be automated; creates
  Android boilerplate that must be deleted, and does not include Biome.
- `npx create-expo-module --local` — interactive; creates Android/web boilerplate to delete.
- TypeScript `7.0.2` (brief's initial table) — rejected by owner answer: use SDK-governed version.

**`modules/chronos-sensors/src/index.ts`** — full public interface:
```ts
import { requireNativeModule } from 'expo-modules-core';

/**
 * Public interface of the ChronosSensors native module.
 * In T0.4 only hello() exists; T2.1 adds the full sensor API.
 */
export type ChronosSensorsModuleType = {
  /** Returns a greeting string to prove the native bridge is working. */
  hello(): string;
};

/** Fallback used in Jest / Expo Go where the native module is not linked. */
const stub: ChronosSensorsModuleType = {
  hello: () => 'ChronosSensors unavailable',
};

function loadModule(): ChronosSensorsModuleType {
  try {
    return requireNativeModule<ChronosSensorsModuleType>('ChronosSensors');
  } catch {
    // Native module is not linked (Jest, Expo Go).
    return stub;
  }
}

const ChronosSensors: ChronosSensorsModuleType = loadModule();

export { ChronosSensors };
export default ChronosSensors;
```
