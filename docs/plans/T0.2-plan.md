# T0.2 Plan: GitHub Bootstrap

## 1. Summary

T0.2 verifies the already-created bootstrap infrastructure and adds tooling to prevent drift
between the ruleset JSON and the CI workflow job names. When done:
- `scripts/bootstrap-github.sh chronos-ai private` runs idempotently with clear messages for the
  three features that require GitHub Pro or a public repo (secret scanning, environment reviewers,
  ruleset).
- `just ruleset-check` (bash + python3 stdlib) asserts the `required_status_checks` contexts in
  `scripts/github-ruleset.json` match the job names in `.github/workflows/ci.yml`, wired into
  CI and a pre-commit hook.
- `docs/11-implementation-plan.md` has updated T0.2 acceptance criteria and a new T6.7 task for
  when server-side protection becomes available.

## 2. Design

**Approach:** T0.2 is a verification + lightweight tooling task; no app code is touched.

- `scripts/ruleset-check.py`: a pure-Python stdlib script (json + re + sys) that parses both
  files and compares sets. Chosen over bash jq/yq to avoid adding tools not in the justfile.
- Pre-commit hook: local hook in `.pre-commit-config.yaml` that runs `scripts/ruleset-check.py`
  when `scripts/github-ruleset.json` or `.github/workflows/ci.yml` changes.
- CI wire-in: `just ruleset-check` called in the `api` job after `just check-api` so it runs on
  every PR (no extra job needed; these two files are root-level and always checked out).
- No new Python package deps — python3 stdlib only.

**Rejected:** shell-only jq+yq approach — would add new tool deps.
**Rejected:** separate CI job for ruleset-check — adds clutter; `api` job always runs.

### Step 2 — Create `scripts/ruleset-check.py`

**Files:** `scripts/ruleset-check.py`

**Full public interface:**

```python
#!/usr/bin/env python3
"""
ruleset-check: assert that required_status_checks contexts in
scripts/github-ruleset.json equal the top-level job keys in
.github/workflows/ci.yml.  Uses only the stdlib.

Exit 0 on success, 1 on mismatch or parse failure.
Usage: python3 scripts/ruleset-check.py [repo-root]
"""
import json, re, sys
from pathlib import Path

def load_ruleset_contexts(root: Path) -> set[str]: ...
def load_ci_jobs(root: Path) -> set[str]: ...
def main() -> int: ...

if __name__ == "__main__":
    sys.exit(main())
```

- `load_ruleset_contexts`: reads `scripts/github-ruleset.json`, finds the rule with
  `"type": "required_status_checks"`, returns `{c["context"] for c in params["required_status_checks"]}`.
- `load_ci_jobs`: reads `.github/workflows/ci.yml` with a regex `^([a-z][a-z0-9_-]*):\s*$` on
  the `jobs:` block — no yaml dep needed; job names are simple identifiers.
- `main`: compares the two sets; prints a clear diff if they differ; exits 0 if equal.

**Tests (inline assertions verified by the script itself):**
- Matching sets → exit 0
- Ruleset has extra context "deploy" → exit 1, prints "in ruleset but not in ci.yml: deploy"
- CI has extra job "deploy" → exit 1, prints "in ci.yml but not in ruleset: deploy"

**Verify:** `python3 scripts/ruleset-check.py && echo PASS`

### Step 5 — Add pre-commit hook

**Files:** `.pre-commit-config.yaml`

Add hook entry:
```yaml
      - id: ruleset-check
        name: ruleset contexts match CI job names
        entry: python3 scripts/ruleset-check.py
        language: system
        files: ^(scripts/github-ruleset\.json|\.github/workflows/ci\.yml)$
        pass_filenames: false
```

**Verify:** `pre-commit run ruleset-check --all-files && echo PASS`

   the repo goes public/Pro in T6.7.

   pass actionlint and zizmor.

5. `docs/11-implementation-plan.md` T6.7 — must depend on T0.2, must capture all three
   features (ruleset, secret scanning + push protection, environment reviewers).
