# T2.6 — Settings implementation plan

## 1. Summary

Add a protected settings screen for preserved whole-document wake-rule editing and three reel
preferences. Every save is explicit and read back. Optional SHA preconditions prevent stale phone
drafts from overwriting newer rules. A bounded visible test-push endpoint reports ticket outcomes
honestly. Existing tables and dependencies suffice; physical delivery remains pending.

## 2. Design

- Wake drafts clone the complete generated `WakeRules`; controls change only selected leaf values.
  Penalties, conditions, holiday/cadence/boundary fields and schema version remain untouched.
- `activate_new_version(..., expected_sha: str | None = None)` obtains a SQLite write reservation
  through a conditional no-change UPDATE on the active SHA inside the activation savepoint,
  then checks/activates under that reservation. A stale differing draft raises `RulesConflict`;
  identical active content stays a no-op. Headerless legacy callers retain their behavior.
- Raw award rows are checked before coercion; reweight values use strict bounded integers.
  Threshold unions and penalty math are unchanged. API commit invalidates the rules cache again
  after commit. GET uses the configured YAML path for provenance.
- GET/PATCH config projects only theme (`auto|dawn|mono|ink`), render mode (`eager|on_trigger`)
  and requested Pexels boolean, each with default/env/db origin. Pexels key availability and
  effective enabled flag are separate, never the key. The future pipeline is explicitly pending.
- A dedicated authenticated test action has no caller-selected destination/payload. A 5-second
  timeout and one-attempt push-client method avoid automatic duplicate sends. A stricter limiter
  and coalesced mobile action bound repeats. Audit records contain a fixed token-free payload;
  accepted tickets are not delivery confirmation. Shared client lifespan exists with scheduler off.
- Client fixed-route allowlist, 32-KiB body limit, immediate auth invalidation and lease guards stay.
  Structured validation issues use bounded allowlisted paths and fixed messages, never raw values.
- Focus-owned controller cancels reads/writes on background/blur, keeps dirty drafts, verifies
  ambiguous writes by GET, and requires explicit reload/reapply after a conflict. No offline writes.
- Rejected: partial rule reconstruction (drops advanced fields); arbitrary config/admin API
  (exposes secrets); automatic push retries (duplicates uncertain sends); new UI/dependency library.

## 4. Steps

1. Backend rule contract: add `RulesConflict`, optional `expected_sha`, compare-and-reserve SQL
   `UPDATE rule_versions SET active=1 WHERE active=1 AND sha256=:expected`, then activation in the
   same savepoint. Expose quoted SHA If-Match, bounded header rejection, 409 `rules_conflict`,
   concrete `{version:int, created:bool}` success DTO. Validate raw award slots as
   `type(value) is int and value >= 0`; reweight strict integers >=0. Preserve threshold types.
   Test 70→71 creates version+1, identical no-op/legacy, two concurrent distinct drafts only one
   accepted, invalid award values leave active version/cache unchanged, custom YAML metadata.
   Verify `uv run pytest tests/test_config_wake.py tests/wake/test_rules.py` plus ruff/pyright.
2. Preferences/push: GET/PATCH typed projection over existing Setting rows; PATCH restricts exact
   fields and rejects null/unknown/incorrect types before atomic write. Add safe environment
   defaults and secret Pexels key. Add visible title/body/sound excluding absent fields to preserve
   silent wire shape. `send_once(messages)` uses one HTTP attempt. Test route records fixed audit,
   resolves day via device tz/rules, sends with `content_available=False`, bounds attempt to5s,
   reports accepted/failed/unavailable/unknown without token/provider details. No counters mutate.
   Test real httpx fake transport single attempt, fake push, timeout, throttle, missing token,
   no secrets and lifespan close. Verify focused pytest, ruff/pyright; `just gen-types` freshness.
3. Mobile: runtime validate config/rules/save/push DTOs within existing transport limit. Add exact
   GET/PUT wake, GET/PATCH config, POST test methods and bounded safe field issues. Clone full
   document; input parsers reject malformed values without coercing bool/string thresholds.
   Controller exposes activate/refresh/edit/saveRules/savePreferences/testPush/reload/subscribe;
   coalesces actions, lease/generation/abort guards, never overwrites dirty drafts. Saves use
   original SHA plus GET equality before success, retaining uncertain drafts. Protected screen
   renders selected fields and preserved advanced configuration, version/provenance and future
   capability caveats. Tests cover preserved custom rules, dirty refresh, stale conflict,
   timeout-after-commit readback, forbidden routes, malformed/huge errors, background/re-pair,
   repeated push taps and every fixture section. Verify Jest, both TypeScript projects, Biome.
4. Acceptance/docs: restart only verified isolated API18444/scheduler off to load routes, retain
   existing Simulator/MetroIPv4. Owner changes confirm70→71 and confirms readback/new version;
   verify no-op and invalid save unchanged, preferences readback, unavailable physical push.
   Restore isolated rules deliberately, record exact original/changed/restored SHA/version.
   Fake push proof stays automated, never called APNs delivery. Run `just check` and
   `just security` on final code, record outputs and exact pending hardware checklist, commit.
