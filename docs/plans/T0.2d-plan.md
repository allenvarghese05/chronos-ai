# T0.2d Plan: Dependabot security-only for pip/npm; allow `deps` PR scope

## 1. Summary

Fixes two Dependabot misconfigurations: (1) pip/npm ecosystems were opening version-bump PRs
because `open-pull-requests-limit: 5` (not 0) was set — changing it to 0 stops version updates
while security updates continue (GitHub ignores the limit for security). (2) GitHub Actions
Dependabot PRs use title `ci(deps): …` but `deps` was not an allowed scope in `pr-title.yml`,
blocking PRs #7, #10, #17. Policy is formalized as ADR D33.

## 2. Design

- **`open-pull-requests-limit: 0`** for pip/npm: the only documented GitHub mechanism to disable
  version updates while keeping security updates active. Groups are kept so security updates are
  still batched into one PR per ecosystem.
- **Add `deps` to pr-title scopes**: owner-confirmed approach; simpler than changing Dependabot's
  commit-message prefix syntax.
- **ADR D33**: short record so the policy survives future Dependabot config edits.
- Rejected: changing `commit-message.prefix` to `ci(ci)` — Dependabot does not support nested
  scope syntax in prefix.
- Rejected: disabling Dependabot groups — groups are still useful for batching security updates.

## 4. Steps

### Step 1 — Fix `.github/dependabot.yml`

**Files:** `.github/dependabot.yml`

Change `open-pull-requests-limit: 5` → `open-pull-requests-limit: 0` for all three pip/npm
entries. Rewrite header comment to state the mechanism accurately.

**Verify:** `cat .github/dependabot.yml | grep open-pull-requests-limit` shows three `0` entries.
`uvx --from actionlint-py actionlint .github/dependabot.yml || true` (actionlint skips yml).

**Commit:** `chore(ci): T0.2d step 1 set dependabot limit 0 for pip/npm`

---

### Step 2 — Add `deps` scope to `pr-title.yml`

**Files:** `.github/workflows/pr-title.yml`

Add `deps` after `release` in the scopes block.

**Verify:** `grep deps .github/workflows/pr-title.yml` shows the scope.
`uvx --from actionlint-py actionlint .github/workflows/pr-title.yml`

**Commit:** `ci(ci): T0.2d step 2 allow deps scope in pr-title`
