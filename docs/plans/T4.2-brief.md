# T4.2 — TTS job (brief)

Branch `t4-2-tts`, stacked on `t4-1-assets` (#47).

| ID | Task | Size | Depends | Acceptance criteria |
|---|---|---|---|---|
| T4.2 | TTS job: `kokoro-onnx` integration, per-scene WAVs, silence padding, concat, loudnorm, `tts.json`; edge-tts fallback; model download in `just models` | M | T4.1 | `@pytest.mark.kokoro` produces a WAV of 50–70 s for the fixture script; unit tests for concat/timing with synthetic audio; fallback path tested with a fake |

Decisions made overnight under the owner's go-ahead:

1. **Dependencies.** `kokoro-onnx==0.6.1` and `edge-tts==7.3.1`, both named in the task. `numpy` comes in transitively with kokoro-onnx and is used directly for PCM.
2. **No audio library.** WAV I/O uses stdlib `wave`. ffmpeg does only loudnorm (`voice.wav`) and the MP3 preview (`voice.mp3`). Single-pass loudnorm keeps the length, so timings from sample counts hold (tested to ±50 ms).
3. **Speed 1.15.** `af_heart` measured ~142 wpm at 1.0; 1.15 gives ~163 wpm, which matches the budget in docs/07.
4. **The template fills ~60 s.** It now uses the top of the per-story range (24 words for 6 stories). The real Kokoro run: 169 words, 59.6 s (AC 50–70 s).
5. **Fallback per scene.** edge-tts is used when Kokoro raises or returns under 1 s. Because edge-tts sends text to Microsoft, `CHRONOS_EDGE_TTS_ENABLED` can switch it off. The licence is `edge_tts` only when every scene used it.
6. **Absolute tool paths.** `ffmpeg_bin`/`ffprobe_bin` are resolved with `shutil.which` at settings time, because job processes have a minimal `PATH`. `models_dir` is the repo's `data/models`.
7. **Error text.** ffmpeg errors report the exit code only; raw stderr is never surfaced (`media.subprocess` contract).
8. **`just models`** already downloads the Kokoro files (T0.6), so nothing changed there.
