# T5.4 — Notification tap deep link (brief)

Branch `t5-4-deeplink`, stacked on `t5-3-feed-player` (#54).

| ID | Task | Size | Depends | Acceptance criteria |
|---|---|---|---|---|
| T5.4 | Notification tap deep link `chronos://reel/<id>` → player; cold-start and warm-start handling; badge clear | S | T5.3 | Tapping the push from lock screen opens the reel in both cold and warm start |

Decisions made overnight under the owner's go-ahead:

1. **Routing.** `useReelDeepLinks()` in the root layout.
   - **Warm start:** `addNotificationResponseReceivedListener`.
   - **Cold start:** `getLastNotificationResponseAsync()`, handled once.
   - `reel_ready` opens `/reel/<id>` (the id must match the ULID pattern); `text_fallback` opens home; other payloads are ignored.
2. **`chronos://reel/<id>`** is routed by expo-router itself (scheme `chronos`, route `reel/[id]`). The player route re-validates the id.
3. **Badge** is cleared on mount and whenever the app becomes active.
4. **`expo-notifications` is loaded lazily**, as in T2.2.
5. **Manual check is still owner-pending:** tap the push from the lock screen with the app killed (cold) and backgrounded (warm).
