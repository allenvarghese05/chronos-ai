# T5.3 — Feed and player screens (brief)

Branch `t5-3-feed-player`, stacked on `t5-2-delivery` (#53).

| ID | Task | Size | Depends | Acceptance criteria |
|---|---|---|---|---|
| T5.3 | Feed + player screens: vertical pager, `expo-video` player, captions overlay from `captions.json`, source sheet, save/delete, empty state with day status, thumbnail list | L | T2.2, T5.1 | Jest for pager state/caption overlay; manual: swipe through today's reel, toggle captions, open a source link, save, delete |

Decisions made overnight under the owner's go-ahead:

1. **Feed at the top of the home screen** (today's plus saved reels with thumbnails). The existing device, telemetry and pairing controls stay below it, so nothing T2.x verified is removed.
2. **Player** (`/reel/[id]`). Full-screen `expo-video`, plus a transparent vertical pager with one page per scene:
   - Swiping seeks the video to that scene.
   - Playback scrolls the pager along.
   - Each story page has a "Read on <source> ↗" chip that opens the article.
   - The toolbar has CC (caption toggle), Save/Saved and Delete (with confirmation).
3. **Captions overlay** is built from `captions.json`, in lines of up to 5 words with the active word highlighted, like the renderer.
4. **Security.**
   - Reel endpoints are added to the client's **explicit path allowlist**; public ids must match the ULID pattern, so a malformed id never leaves the phone.
   - Every response is validated before use.
   - Media and caption URLs are used only if their origin is the paired laptop's API.
5. **Empty state.** Shows a plain message. Day status (`/v1/day/...`) is not shown yet, which keeps this PR to the reels API.
6. **Manual device check is still owner-pending:** swipe, toggle captions, open a source, save, delete on the iPhone.
