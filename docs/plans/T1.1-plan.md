# T1.1 Plan: Tables + Migration 0001

## 1. Summary

Implements the complete SQLite schema for Chronos-AI: eight tables
(`devices`, `pairing_codes`, `rule_versions`, `telemetry_events`,
`wake_evaluations`, `days`, `day_transitions`, `settings`) with all
constraints, indexes and enum check-constraints. Delivers shared helpers
(`chronos.time`, `chronos.enums`, `chronos.ids`) used by every later task,
SQLModel table classes in `chronos.models.*`, Alembic migration `0001`, and a
full test suite covering upgrade/downgrade, FK enforcement, partial unique
index, composite keys, and factory smoke-tests.

## 2. Design

**Approach:** SQLModel `table=True` classes (consistent with T0.3 scaffold) in
a `models/` package, one module per aggregate. `alembic revision
--autogenerate` produces the skeleton; the file is hand-reviewed and amended
for: partial unique index (sqlite_where), composite FK, and CHECK constraints
(which autogenerate omits). Naming convention: `pk_`, `fk_`, `uq_`, `ix_`,
`ck_` prefixes applied explicitly via `__table_args__`.

**Alternatives rejected:**
- Plain SQLAlchemy `Table()` core — loses Pydantic integration needed in T1.2+.
- `Relationship()` helpers — owner explicitly rejected (answer 1); joins are explicit.
- Hand-writing migration from scratch — autogenerate + hand-review is faster and keeps model/schema in sync; a metadata-parity test catches drift.

### Step 2 — SQLModel table classes in `chronos/models/`

**Files:** `src/chronos/models/__init__.py`, `src/chronos/models/devices.py`,
`src/chronos/models/wake.py`, `src/chronos/models/settings.py`

**Key design decisions:**
- `SQLModel` with `table=True` for all 8 tables.
- `id: Optional[int] = Field(default=None, primary_key=True)` pattern.
- `__table_args__` on each class for named constraints and indexes.
- Enums stored as TEXT; CHECK constraints use `sa_column=Column(String, CheckConstraint(..., name="ck_..."))`.
- Composite PK on `days` via `__table_args__` `PrimaryKeyConstraint`.
- Partial unique index on `rule_versions.active` via `Index(..., sqlite_where=text("active = 1"))`.
- Composite FK from `day_transitions` to `days` via `ForeignKeyConstraint`.

**`models/__init__.py`** — imports all classes so `SQLModel.metadata` is fully populated:
```python
from chronos.models.devices import Device, PairingCode as PairingCode

    RuleVersion as RuleVersion,
    TelemetryEvent as TelemetryEvent,
    WakeEvaluation as WakeEvaluation,
    Day as Day,
    DayTransition as DayTransition,
)
from chronos.models.settings import Setting as Setting

__all__ = [
    "Device", "PairingCode", "RuleVersion", "TelemetryEvent",
```

**Full table class signatures:**

`devices.py`:
```python
class Device(SQLModel, table=True):
    __tablename__ = "devices"
    __table_args__ = (
        UniqueConstraint("public_id", name="uq_devices_public_id"),
        UniqueConstraint("token_hash", name="uq_devices_token_hash"),
        CheckConstraint("status IN ('active','revoked')", name="ck_devices_status"),
    )
    id: Optional[int] = Field(default=None, primary_key=True)
    public_id: str = Field(sa_column=Column("public_id", String, nullable=False))
    name: str
    token_hash: str
    expo_push_token: Optional[str] = None
    tz: str
    app_version: Optional[str] = None
    ios_version: Optional[str] = None
    model: Optional[str] = None
    status: str  # DeviceStatus
    created_at: str
    last_seen_at: str
    revoked_at: Optional[str] = None

class PairingCode(SQLModel, table=True):
    __tablename__ = "pairing_codes"
    __table_args__ = (
        UniqueConstraint("code_hash", name="uq_pairing_codes_code_hash"),
    )
    id: Optional[int] = Field(default=None, primary_key=True)
    code_hash: str
    expires_at: str
    consumed_at: Optional[str] = None
    attempts: int = 0
```

`wake.py` — detailed column specs per data model §2.2.

## 7. Out of scope

- No `reels`, `briefs`, `brief_items`, `items`, `sources`, `jobs`, `push_notifications` tables.
- No `Relationship()` helpers.
- No app-level token hashing (T1.2 responsibility).
- No `local_date` derivation logic (T1.6 responsibility).
- No Pydantic request/response DTOs (T1.2+ responsibility).
- No `chronos db migrate` CLI changes unless existing command breaks.

## 8. Review focus

1. **Composite FK in `day_transitions`** (`ForeignKeyConstraint` referencing `days(local_date, device_id)`) — SQLite batch mode must handle this correctly.
2. **Partial unique index** `ix_rule_versions_active_one` with `sqlite_where=text("active = 1")` — verify the WHERE clause is in the DDL.
3. **CHECK constraints** in `__table_args__` — autogenerate omits them; confirm they are hand-added to the migration and tested.
4. **`metadata_vs_inspect` parity test** — must cover nullability and PK correctness, not just table names.
5. **pyright strict on SQLModel 0.0.47** — `Optional[int]` PK pattern and `sa_column=Column(...)` usages must be type-safe; no `type: ignore` comments.
