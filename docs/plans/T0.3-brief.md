## Why it matters

This scaffold establishes the Python backend structure that all M1–M5 tasks depend on. A broken or misaligned foundation forces rework in pairing (T1.2), telemetry (T1.6), config (T1.4), the job queue (T3.1), media pipeline (M4), and delivery (T5.1–T5.2). The app factory and CLI must be shaped to support type generation (T0.7), migrations (T1.1), and the test harness (T1.2+). Incorrect PRAGMA settings, weak settings validation or misplaced structlog setup will ripple through every worker job and server log. The `pyright strict` requirement locks in type safety from day one.

## Governing decisions

- **D10**: Single Python 3.12 process (API + in-process worker/scheduler); no Redis/Celery. `settings` object from `pydantic-settings` with `CHRONOS_` prefix. `SQLModel` over raw SQLAlchemy for ORM + Pydantic integration.
- **D16**: HTTPS only; binds to LAN interface (not `0.0.0.0`); `/readyz` checks reachability, not just startup.
- **D29**: Config via Pydantic `Settings` and YAML for rules/sources; schema validated on startup; `chronos config validate` CLI.
- **D28**: `structlog` JSON logs with rotation; no secrets in logs.
- **D23**: `.env` gitignored; `.env.example` documents every variable with placeholder; settings use `SecretStr` for tokens/keys.

## Edge cases

1. **Missing `.env` or incomplete settings**: Settings validation on app startup must reject missing required vars. Test with a minimal `.env.example` and verify startup fails with a clear error if `CHRONOS_SECRET_KEY` is unset.

2. **SQLite WAL mode not enabled**: If `PRAGMA journal_mode=WAL` is not set, concurrent access will fail. Test by creating DB, checking `PRAGMA journal_mode`, and verifying it returns "wal".

3. **Foreign key constraints disabled**: Default SQLite behavior is `PRAGMA foreign_keys=OFF`. Must be set `ON` in the engine to catch schema bugs early. Test by attempting a DELETE on a parent row with children and verifying INTEGRITY_CONSTRAINT error.

4. **Timezone info stored as naive datetime**: Server must always use UTC and derive local dates with `datetime.datetime.now(datetime.timezone.utc)`. Test by mocking system time and verifying the epoch is correct.

5. **Structlog not configured early**: If structlog setup runs after imports, third-party libraries may log unsafely. Setup must happen in `chronos.observability.configure()` called at the top of `main()` before FastAPI app creation.

6. **Missing HTTPS certificate files**: If `CHRONOS_CERT_PATH` or `CHRONOS_KEY_PATH` point to missing files and `CHRONOS_ENV != "test"`, the app must refuse to start with a clear error. Test with a non-existent path.

7. **pyright cache stale**: If a type changes and `~/.cache/pyright-python` is not cleared, CI may report false negatives. The CI workflow includes a cache restore; ensure it is keyed by `uv.lock`.

8. **Pytest discovery picks up unrelated files**: The `tests/` directory must have an `__init__.py` to avoid pytest collecting e.g. `alembic/versions/` as tests. Glob patterns in `pytest.ini` or `pyproject.toml` control this.

9. **Config validation in pre-commit but config file doesn't exist yet**: `chronos config validate` is called in the pre-commit hook for `services/api/config/*.yaml`. If no YAML files exist, the hook must skip gracefully (exit 0). Add a check in the script.

10. **Bandit false positive on `assert` in tests**: Bandit (security scanner) flags `assert` statements in production code. Ensure all asserts are in `tests/` only. If any occur in `src/`, fix them before commit.

## Proposed approach

1. **Project scaffold** (`uv init --name chronos`): Create `pyproject.toml` with `src/chronos` layout, pin FastAPI/uvicorn/pydantic/sqlmodel/alembic/structlog/typer exactly, add dev dependencies (ruff, pyright, pytest, pytest-cov, bandit, pip-audit, hypothesis, time-machine, freezegun). Run `uv sync --locked` to generate `uv.lock`.

2. **Settings** (`chronos.config.Settings`): Pydantic v2 class inheriting from `pydantic_settings.BaseSettings`, with field validators for env vars (`CHRONOS_DATABASE_URL`, `CHRONOS_SECRET_KEY`, `CHRONOS_API_BIND_HOST/PORT`, `CHRONOS_ENV`, `CHRONOS_CERT_PATH`, `CHRONOS_KEY_PATH`, `CHRONOS_LOG_DIR`), plus placeholders for tool configs. Use `SecretStr` for sensitive fields. Test with a `.env` file in the test.

3. **Database** (`chronos.database`): SQLAlchemy 2.0 async engine (if not using async yet, then sync) pointing to `data/chronos.db`, with `PRAGMA journal_mode=WAL; foreign_keys=ON; busy_timeout=5000`. SQLModel `declarative_base()` for models. Alembic init to `alembic/` with the generated `env.py` pointing to the engine.

4. **Observability** (`chronos.observability`): structlog configuration function setting up JSON formatting, file rotation (size 50 MB, 14-day retention simulated by truncation in dev), and a metrics registry (stub). Redact secrets in a processor before logging. Integrate into the app startup.

5. **App factory** (`chronos.main.create_app()`): FastAPI `app = FastAPI(...)` with the Settings singleton, database engine setup, structlog configuration, CORS (LAN only), and routers. Include exception handlers for HTTP 422 (validation), 404, 500. Return `app`.

6. **CLI** (`chronos.cli`, Typer app): Commands `serve` (start uvicorn with cert/key binding), `db migrate` (alembic upgrade head), `config validate` (placeholder for T1.4), `doctor` (stub for T0.6). Each command reads settings, sets up logging, and executes.

7. **Routers** (`chronos.routers.health`): `/healthz` (no auth, liveness) and `/readyz` (liveness + DB check). Both endpoints read settings and return JSON.

8. **Tests**: `test_config.py` (settings loading from .env, validation on missing vars), `test_health.py` (GET /healthz 200, GET /readyz 200 with DB up, 503 if DB mock fails). Use `pytest` fixtures for app (TestClient), temp SQLite, and freezegun/time-machine for clock mocking.

9. **CI integration**: Ensure `just check-api` runs ruff, pyright, pytest, bandit, config validate (stub). Verify `uv export --locked` for pip-audit in CI. Pre-commit hook for gitleaks, no-data-dir, trailing-whitespace.

This approach keeps the scaffold minimal, isolated, and testable; all path-dependent logic (window, scoring, job queue, media subprocess) is deferred to later tasks.

## Risks

1. **uv.lock regenerated by accident**: If a dev runs `uv sync` without `--locked` or modifies `pyproject.toml` and re-locks, the lock file will change. **Mitigation**: Document in README that `uv sync --locked` is immutable; CI checks `git diff --exit-code` on uv.lock post-sync. Enforce via pre-commit hook that forbids uncommitted changes to uv.lock without explicit review.

2. **PRAGMA settings not applied**: If the engine is created before the pragmas are set, concurrent writes will cause SQLITE_BUSY errors or corruption. **Mitigation**: Set pragmas in `SQLAlchemy.create_engine(..., connect_args={...})` or immediately after engine creation with a test connection; pytest fixture validates by reading `PRAGMA journal_mode`.

3. **Secrets logged by third-party libraries**: Even with structlog redaction, a library may log a full traceback with env vars. **Mitigation**: Test with a canary token in `.env` and grep the test logs for it; fail if found. Pre-commit hook could use gitleaks to scan the log output.

4. **pyright strict mode enforces too much**: If strict is truly strict, legitimate Python idioms (e.g., optional fields in models) will fail. **Mitigation**: Use `pyrightconfig.json` with `"typeCheckingMode": "strict"` set at the repo level; handle cases with type: ignore comments and a comment explaining why. Ensure all T0.3 additions pass strict with zero ignores.

5. **SQLite in-memory mode used in tests**: If a test accidentally uses `:memory:`, it will not test WAL mode. **Mitigation**: Use `tempfile.NamedTemporaryFile()` for test DB; assert `PRAGMA journal_mode = 'wal'` in a conftest fixture.

6. **Settings object not singleton**: Multiple instances of Settings created (via re-reads of .env) can cause inconsistencies. **Mitigation**: Create Settings once in the FastAPI app and store in `app.state.settings` or a module-level constant; tests mock it.

7. **Alembic env.py not updated for SQLModel**: Default Alembic template uses SQLAlchemy directly. **Mitigation**: After `alembic init`, manually edit `env.py` to import and use `SQLModel.metadata` and set `target_metadata = SQLModel.metadata`.

8. **No integration test for the app factory**: If `create_app()` has a typo or missing import, it will only fail at runtime. **Mitigation**: Add `test_main.py` with `from chronos.main import create_app; app = create_app(); assert isinstance(app, FastAPI)`.

9. **Pyright unable to resolve SQLModel types**: SQLModel has some typing quirks. **Mitigation**: Test pyright locally before push; if errors occur, add a `py.typed` marker or minimal type stubs to suppress false positives (document in the task plan).

10. **Rate limiting or auth missing from the scaffold**: `/readyz` and `/healthz` must not require auth (they are health checks); later tasks (T1.2) will add auth to `/v1/*` endpoints. **Mitigation**: Explicitly route these at the root level, not under `/v1`, and document in the endpoint that they are unauthenticated.

Approved with the orchestrator's four clarifications:

1. TLS: no external proxy. `chronos serve` uses uvicorn's built-in `ssl_certfile` / `ssl_keyfile`
   from Settings (`CHRONOS_TLS_CERT`, `CHRONOS_TLS_KEY`). Plain HTTP is allowed only when
   `CHRONOS_ENV` is `dev` or `test`; in `prod` missing cert/key is a startup error.
2. Database: synchronous SQLAlchemy engine and sessions (no async engine). PRAGMAs applied on every
   connection via the `connect` event. Tests use a temporary *file* database, never `:memory:`.
3. Clock: `time-machine` only (no freezegun).
4. No CORS middleware (no browser client).

Also: exact versions as recorded in §Current state; pyright `strict`; Python `>=3.12,<3.13`.
