# T1.4 Plan: Rules Loader `wake/rules.py`

## 1. Summary

Deliver the complete schema, lifecycle, and API for Chronos-AI wake-engine rules:
- `config/wake_rules.yaml` — versioned v1 rule document (source of truth).
- `wake/signals.py` — `SignalSpec` registry covering all phone + server-derived fields.
- `wake/conditions.py` — tiny `Condition` parser (`>=,>,<=,<,==,in`) with `.evaluate()`.
- `wake/rules.py` — strict Pydantic models (`WakeRules`, `WakeRulesWindow`, `Rule`, `Penalty`, `Thresholds`), YAML loader, canonical-JSON SHA-256, `RulesCache`, atomic DB versioning helpers, startup logic.
- `api/config_wake.py` — `GET/PUT /v1/config/wake` router (require_device, rate-limit, RFC 9457).
- CLI: `chronos config validate` (real) and `chronos config apply-yaml`.
- Tests covering all 20 edge cases from the brief plus concurrency, startup, and CLI.

## 2. Design

**Pydantic models with `extra="forbid"`** enforce validation at parse time; errors surface as `ValidationError` with `loc` tuples, which are re-emitted as `errors: [{loc, msg, type}]` in the 422 `rules_invalid` problem+json body.

**`WakeRulesWindow`** wraps the YAML-native `weekday: {start, end}` / `weekend: {start, end}` shape and exposes `to_window_config() -> WindowConfig` for the scoring engine.

**Signal registry** (`SignalSpec` in `signals.py`) is the single authoritative source of signal names, kinds (numeric/bool/enum), and allowed enum values; `rules.py` validators look up each rule's signal against it; `scoring.py` (T1.5) reuses it.

**Condition parser** is isolated in `conditions.py` so T1.5 can call it without re-parsing. A `Condition` instance holds operator + operand and exposes `evaluate(value) -> bool`.

**Canonical JSON**: `model_dump(mode="json")` → `json.dumps(sort_keys=True, separators=(",",":"))` → SHA-256 hex. Lossless: `WakeRules.model_validate_json(canonical_json(r)) == r`.

**Atomic versioning** uses an explicit SQLAlchemy transaction: `SELECT MAX(version)` → deactivate current (`active=0`) → `INSERT ... active=1`; if the insert raises the whole transaction rolls back and the previously-active row is unchanged.

**`RulesCache`** is a module-level singleton with `get_effective(session)` (returns cached `(WakeRules, RuleVersion)` or reloads from DB) and `invalidate()` (called by PUT and `apply-yaml`). Thread-safe via a `threading.Lock`.

**Alternatives rejected:**
- Using Pydantic's built-in YAML loader (opt-in; requires extra dep).
- Storing `WindowConfig` directly in YAML (field names don't match the `weekday.start` nesting in docs/03 §4; `WakeRulesWindow` preserves the documented shape).
- Class-level caching on `Settings` (simpler here; D10 single-process).

**Cross-field validators (complete list):**
1. `rules` non-empty.
2. Unique rule IDs.
3. Each rule `signal` in `SIGNALS`.
4. `cap ≥ max(points row pts values)` for each rule.
5. Numeric signals: threshold values strictly descending.
6. Bool signals: exactly one threshold row; threshold must be `True` or `False`.
7. Enum signals: each threshold value must be in `spec.enum_values`.
8. `thresholds.strong ≤ thresholds.confirm`.

10. `window.weekday.start < weekday.end` and `window.weekend.start < weekend.end`.
11. `window.holidays_as_weekend` elements parse as ISO dates.
12. `reweight_without_pedometer` keys ⊆ rule IDs.
13. `sum(reweight_without_pedometer.values()) ≤ 100`.
14. `Penalty.when` values parseable by `parse_condition`.
15. `bonus_consecutive.points ≥ 0` (enforced by Field constraint).

```python
    device: Device = Depends(require_device),
    session: Session = Depends(get_session_dep),

    # ValidationError from body parsing → 422 rules_invalid (hook on this router only)
    # returns 200 if SHA identical, 201 if new version
```

The 422 `rules_invalid` hook is registered as an `exception_handler` on the router via an `APIRouter` dependency or on the `FastAPI` app with path filtering. Because `WakeRules` body validation errors come from FastAPI's `RequestValidationError` before the handler is called, I use a **route-level approach**: catch `ValidationError` in the PUT handler body and re-raise as `ProblemException(422, "rules_invalid", ...)` with `errors` list extracted from `e.errors()`. For body validation, FastAPI calls the validator before the handler — so I'll declare `body: Any` and call `WakeRules.model_validate(body)` inside the handler, catching `ValidationError` there. This gives us field-level errors without a global handler override.
