# T0.4b Brief: Prebuild and run dev-client on the iOS Simulator; verify hello() from the Swift module

## Task

**ID:** T0.4b
**Title:** Prebuild and run the dev-client on the iOS Simulator; verify hello() from the Swift module; the physical-device install is deferred to T2.4's device checklist because the owner's iPhone port is broken (MagSafe is charge-only, no data — Xcode cannot see the device).
**Size:** S
**Dependencies:** T0.4
**Acceptance criteria:**
- `expo prebuild --platform ios --clean` succeeds (requires Xcode 16 + CocoaPods; no errors)
- `expo run:ios` installs the dev-client on the iOS Simulator (pinned iPhone 16 Pro, iOS 18.6)
- The screen shows "Hello from ChronosSensors!" (proof the Swift module is linked and returns the correct string, not the JS fallback "ChronosSensors unavailable")

---

## Why it matters

T0.4b completes the mobile app's build and runtime validation on the simulator, which is the only iOS device available on the development machine (the physical iPhone is inaccessible due to port failure). This task proves:
- `expo prebuild` can generate an Xcode project from `app.config.ts` with CocoaPods linking the chronos-sensors Swift module
- The dev-client binary can be built and installed on the simulator
- The TypeScript/Swift bridge is correctly configured and the native module is callable from JavaScript
- The hello() function returns the string from Swift (not the fallback), proving native linking is working

Without T0.4b, the mobile app cannot be tested beyond CI (linting, type-checking, unit tests on ubuntu-latest). The simulator run is the first real runtime proof that the app can execute native code. Device install is deferred to T2.4 (when the owner's iPhone is repaired or replaced, or when MagSafe is bypassed with an adapter).

## Edge cases

1. **Simulator device does not exist or is in wrong state**
   - Input: `xcrun simctl list devices` shows iPhone 16 Pro but it is in a "Shutdown" or "Booted" state with insufficient resources
   - Expected: `expo run:ios` attempts to boot the device automatically; if it fails (e.g., disk full, permissions), the error is clear
   - Test: Run `xcrun simctl erase all` to reset simulators, then `expo run:ios`; if boot fails, see Xcode System Information

2. **Pods download fails (network timeout)**
   - Input: `expo prebuild --platform ios --clean` runs but network is slow or interrupted during `pod install`
   - Expected: Pod installation fails with a clear error; task can be retried
   - Test: Run prebuild with intentional network latency (e.g., via macOS network conditions throttling) and verify error message

3. **Swift module does not link (missing or malformed podspec)**
   - Input: `ios/ChronosSensors.podspec` has a typo or missing dependency
   - Expected: `pod install` or `xcodebuild` fails with a clear error mentioning the pod or library
   - Test: Introduce a typo in podspec `source_files`, run prebuild; error should point to the podspec

4. **Swift module compiles but returns wrong string**
   - Input: `ChronosSensorsModule.swift` `hello()` returns "Hello wrong!" instead of the expected string
   - Expected: App builds and installs, but screen shows the wrong greeting; test visually confirms mismatch
   - Test: Modify the string, rebuild, screenshot the result (does not pass acceptance)

5. **TypeScript bridge does not load the native module (fallback is used instead)**
   - Input: Dev-client is not properly built or the app uses a JS bundle without native linking
   - Expected: Screen shows "ChronosSensors unavailable" (the fallback); this means native module was not found
   - Test: If this occurs, verify `expo run:ios` included the `--dev-client` build; if not, the app used Expo Go instead

6. **Xcode workspace name mismatch with ios-build.yml**
   - Input: `app.config.ts` `name: 'Chronos'` and `slug: 'chronos'` but Expo generates workspace name `Chronos` (not `ChronosAI`)
   - Expected: Prebuild succeeds, but `ios-build.yml` step `xcodebuild -workspace ChronosAI.xcworkspace` fails with "workspace not found"
   - Test: Run prebuild locally, check `ls apps/mobile/ios/*.xcworkspace`; compare with `ios-build.yml` workspace name; update workflow if needed (open question #4)

7. **First run vs. second run: cached state**
   - Input: Run `expo run:ios` twice in succession
   - Expected: First run: several minutes (pod download, Swift compilation); second run: ~1 minute (Metro recompilation only)
   - Test: Measure build times; verify Metro hot reload works on second run

8. **Simulator screen rotation or layout changes**
   - Input: Simulator is rotated or resized after app launch
   - Expected: App layout adapts (portrait-only, per `app.config.ts` `orientation: 'portrait'`); text remains visible
   - Test: Rotate simulator (Cmd+Left/Right arrow); app should not break

9. **App crashes during dev-client initialization**
   - Input: JavaScript error in `src/app.tsx` or module import
   - Expected: Red screen with error message; stack trace shows the line
   - Test: Introduce a syntax error in `app/index.tsx`, run `expo run:ios`; red screen appears

10. **CocoaPods version incompatible with Xcode 16**
    - Input: CocoaPods 1.17.0 (current) is incompatible with Xcode 16.4 (unlikely but possible)
    - Expected: `pod install` fails with a version mismatch error; task requires CocoaPods upgrade or Xcode downgrade
    - Test: This is not reproducible without changing tools; document the constraint; if it occurs, seek new pod version or Xcode patch

## Proposed approach

**Shape of the solution (5–15 lines, not implementation details):**

1. **Verify simulator is available:** Boot iPhone 16 Pro iOS 18.6 if not already running (`xcrun simctl boot <udid>` or auto-boot by `expo run:ios`)

2. **Run `expo prebuild --platform ios --clean`:** Generates `apps/mobile/ios/ChronosAI.xcworkspace` and linked pods; verify exit code 0 and no pod/compilation errors

3. **Start Metro dev-server (if not already running):** `expo run:ios` starts it automatically, but can start separately with `expo start --dev-client` and keep running in a separate terminal

4. **Run `expo run:ios` (no `--device` flag):** Tells Expo to install on an available simulator (will auto-select iPhone 16 Pro if pinned); watch the build log for "Installed" or "Launching" messages

5. **Verify the app screen:** Should display "Hello from ChronosSensors!" exactly (not the fallback "ChronosSensors unavailable"); if fallback appears, native module was not linked; if build fails before screen, check the error log

6. **(Stretch, optional in T0.4b) Add `just mobile-sim` recipe:** Wrapper around `expo run:ios` with or without a pinned simulator name; used for repeated dev runs. Can be deferred if out of scope.

7. **(Required for T2.4 readiness) Update `docs/11-implementation-plan.md`:** Add device-install item to T2.4 acceptance criteria ("device install on physical iPhone with repaired MagSafe or replacement"; depends on hardware repair). Update T0.4b row in M0 table.

8. **Verify `ios-build.yml` workspace/scheme names (open question #4):** Check that generated workspace and scheme names match `xcodebuild` arguments; if not, update the workflow

| Xcode workspace name does not match `ios-build.yml` | Medium | Workspace name is derived from `app.config.ts` `name` and `slug` by Expo; exact format is not fully documented; `ios-build.yml` currently expects `ChronosAI.xcworkspace` and `ChronosAI` scheme | Run prebuild locally, check `ls apps/mobile/ios/*.xcworkspace` and `xcodebuild -list` for scheme names; update workflow if needed (open question #4) |
| First prebuild takes longer than expected | Low | Pod download can take 5–10 minutes on first run; subsequent runs are ~1 minute | Set a reasonable timeout (e.g., 20 min per attempt); document this in task plan |
| Simulator boots but app crashes on launch | Medium | JavaScript error in `src/app.tsx` or the native bridge throws; red screen appears with stack trace | Read the error carefully; common issues: missing dependency, wrong module name, fallback string hardcoded incorrectly |

| App builds but screen is blank or unresponsive | Low | JavaScript error during render, or app is loading; monitor Metro console for errors | Check Metro console for JS errors; wait 10 seconds for initial load; if stuck, kill Metro and retry |
