## 2. Why it matters

The next tasks need durable stage identity, bounded execution and restart recovery rather than an in-memory background callback. A duplicate claim can repeat side effects; an expired lease can be more dangerous if the original process is still running. Different jobs running simultaneously can also exceed the laptop's 16-GB budget even if each row is claimed only once.

Queue ownership, actual execution exclusivity and process cleanup are separate obligations. Successful database fencing alone cannot stop an already running renderer. A timeout on an awaitable or thread likewise does not kill its Python work or descendants. The implementation must prove real termination before retry/reclaim and describe at-least-once recovery honestly: arbitrary future external effects cannot be guaranteed exactly once by this queue.

## 5. Inputs and outputs

| Input | Output / authority |
|---|---|
| Internal validated enqueue(kind,key,payload,priority,limits) | Durable queued row or existing unique row without changing its content/status; explicit no-force semantics. No HTTP enqueue endpoint. |

| Authenticated GET jobs filter/page request | Bounded safe metadata page; no payload, token, path, raw output or traceback. |
| Migration0003 upgrade/downgrade | Five new content/job tables with constraints/indexes and matching registered SQLModel metadata; existing 14 rows and nine earlier tables preserved on downgrade. |

## 6. Constraints

- Do not run heavy handlers inside a database write transaction or keep a SQLite writer lock for an entire stage; that would block telemetry/settings. Claims and fenced state updates are short transactions; OS execution ownership is separate.
- Enforce both same-row exclusivity (via atomic UPDATE with WHERE status/locked_by comparison) and different-row global seriality (via OS file lock). Future completion, failure, retry and reclaim updates must compare status and per-attempt ownership.
- Canonical aware UTC wall time controls persistence/run_after; monotonic elapsed time controls actual execution deadlines. Clock jumps, sleep and expired locks must not justify overlapping still-active jobs. Small injectable clocks/backoff sequences make tests deterministic.
- Bounded payload/object validation and finite attempts/timeouts/priorities; no permissive arbitrary module/command serialization. Handler registration is trusted program code, not content data. Unknown/unregistered kinds must not silently execute or consume work during mixed-version deployment.
- The single wrapper must validate `cwd.resolve()` remains under data root (including symlink escape), take argv lists, allowlist environment (PATH/LANG/LC_ALL/TZ/OMP/MKL only), drain output with ≤65536 bytes retained, and terminate/reap the whole tracked process group on timeout/stop. A malicious child filling stdout must not deadlock or allocate unbounded memory. Error logging must not dump captured secrets.
- Caffeinate and the serial lock must cover the real execution lifetime, including a parent crash/orphaned child, and be released after cleanup. Fail closed if cleanup/ownership cannot be established; never start another heavy job merely because a database timestamp expired.
- Keep JSON storage (draft scripts) distinct from semantic generated-script validity. Tables are groundwork; no source/network fetch, model invocation, artifact hash-skip or retention deletion is claimed by this task.

## 7. Edge cases

| Concrete case | Expected result |
|---|---|
| Two distinct DB connections claim the same due row | One claim/attempt only; the loser gets no work, without duplicate handler execution. |
| Two workers have two different due heavy jobs | Actual execution remains globally serial (OS lock prevents overlap), not merely different-row-safe. Readers/telemetry still proceed. |
| Same(kind,key) enqueued concurrently with different payloads | One durable original row; no silent payload replacement/restart. |
| Priority0 deliver vs. priority10 ingest, same run_after | Stable lower priority then ID wins. Future/not-due rows do not block. |
| Running job exceeds timeout; child ignores TERM and spawned sleeper | Deadline triggers TERM (1 s) → KILL, group reaped, caffeinate cleaned, then retry/failed transition; no residual sleeper. |
| Python handler sleeps/loops instead of spawning a tool | Killable job boundary still enforces deadline via supervisor TERM/KILL; no background thread continues. |
| API/worker crashes while handler/descendant remains alive | Next worker cannot overlap it (OS lock held by supervisor via FD); recovery waits for/terminates execution safely, then reclaims. |
| Attempt A expired, attempt B owns row, A returns late | A's success/failure/requeue/lock-release is rejected by ownership check (locked_by compare); B remains intact. |
| locked_by resembles a PID now reused by unrelated process | Not signaled; DB strings are not authority to kill. Fresh per-attempt owner token prevents this. |
| Laptop sleeps or UTC clock jumps forward/backward | No overlap based solely on lease expiry; monotonic execution bounds and real lock ownership remain authoritative. |
| Attempt1 fails, then2, then3 at max_attempts3 | Persist attempts/run_after with deterministic bounded backoff; final failure has finished time/safe reason and not claimed again. |
| Shutdown arrives during output drain/database busy/child startup | Stop claiming, cancel current work within grace period, reap descendants and preserve fenced state before engine disposal. |
| Two sessions share one Session object | Prohibited; each claim/update/run has its own scoped Session. Tests use independent connections. |
| Huge output or invalid UTF8/nonzero exit with secret-looking text | Drain without blocking, retain only ≤output_limit bytes, safe summary/error code, no raw payload/secret in API or logs. |
| `cwd=data/jobs/link` resolves outside data | Rejected before spawn. Output paths and key-derived directories cannot escape through traversal or symlink. |
| No caffeinate on Linux CI / macOS adapter failure | Platform-safe injected/no-op Linux behavior; explicit safe macOS failure policy, no orphan assertion/child or fabricated success. |
| Future kind has no registered handler in this version | No arbitrary code execution and no fake success; explicit unsupported-kind policy; job remains queued. |
| Item high-bit64 simhash / duplicate source external_id | Reversible signed64 storage convention; named uniqueness constraint prevents duplicates. |
| Brief references nonexistent composite day / brief-item nonexistent item | FK constraint rejects it; brief retention prevents deleting referenced items. |
| Populated0002 DB upgrades then downgrades0003 | Existing pairing/rules/telemetry/push data remain unchanged; only five new tables removed in safe order. |
| GET jobs without/revoked token, bad status/limit/cursor | Existing 401/403/422/429 behavior; no queue mutation or unbounded response. |
| Job payload/error contains bearer/path/feed text | Safe projection omits it; test response/log scan proves absence. |
