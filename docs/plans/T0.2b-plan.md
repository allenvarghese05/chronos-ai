# T0.2b Plan: Deterministic expo-doctor in CI (hotfix)

## 1. Summary

`just check-mobile` and CI job `mobile` currently fail whenever Expo publishes SDK-57 patches, because `expo-doctor` consults Expo's live manifest and compares against pinned versions. T0.2b fixes this by: (a) bumping the four drifted Expo pins to current SDK-57 patch levels (57.0.28 / 57.0.20 / 57.0.26 / 57.0.6), (b) adding `EXPO_DOCTOR_SKIP_DEPENDENCY_VERSION_CHECK=1` inline to the `check-mobile` justfile recipe so neither local nor CI consults the live registry for pass/fail, (c) adding a non-failing weekly advisory step in `audit.yml`, and (d) documenting the policy in ADR D32.

## 2. Design

**Approach:** use the `EXPO_DOCTOR_SKIP_DEPENDENCY_VERSION_CHECK=1` env var (confirmed in expo-doctor 1.20.4 `env.d.ts`) inline in the justfile recipe, so the skip applies identically in local runs and CI (D18). The weekly advisory in `audit.yml` preserves drift visibility without blocking CI (D19, D22).

**Rejected alternatives:**
- Set the env var only in the CI job step: breaks D18 (local and CI must run the same recipe).
- Auto-bump via Dependabot/CI on every patch: live-registry auto-bumps are unpredictable; D32 mandates deliberate bumps only.
- Warn-only flag for expo-doctor: no such flag exists in 1.20.4; env var is the only knob.
- Skip expo-doctor entirely: would remove 20 other checks that catch genuine scaffold errors.

### Step 2 — justfile `check-mobile` recipe: add env var + comment

**Files touched:** `justfile`

**Change:** Replace bare `pnpm exec expo-doctor` line with:

```bash
    # expo-doctor: skip live-manifest version check (deterministic CI per ADR D32);
    # drift visibility preserved by weekly advisory in .github/workflows/audit.yml
    EXPO_DOCTOR_SKIP_DEPENDENCY_VERSION_CHECK=1 pnpm exec expo-doctor
```

The env var is scoped to that single command (shell assignment prefix, not `export`). The standalone `build` recipe does not invoke `expo-doctor` and needs no change.

**Tests:**
- `just check-mobile` exits 0 (21/21 after pin bump, or 20/20 with skip)
- `unset EXPO_DOCTOR_SKIP_DEPENDENCY_VERSION_CHECK && just check-mobile` also exits 0 (recipe sets it unconditionally)

### Step 3 — add advisory step to `audit.yml`

**Files touched:** `.github/workflows/audit.yml`

**Change:** Add after the `JS audit informational (ignored advisories visible)` step:

```yaml
      # Expo SDK drift: informational only (non-failing). Reports current vs SDK-recommended
      # versions of Expo packages weekly. Pins are bumped deliberately in task plans (ADR D32).
      - name: Expo SDK drift (advisory)
        if: ${{ !cancelled() }}
        env:
          EXPO_NO_TELEMETRY: "1"
          CI: "1"
        run: |
          [ -f apps/mobile/package.json ] || { echo "apps/mobile not scaffolded"; exit 0; }
          cd apps/mobile
          pnpm install --frozen-lockfile
          echo "=== Expo SDK drift (from live manifest) ==="
          pnpm exec expo install --check 2>&1 || true
          echo "To bump: cd apps/mobile && pnpm exec expo install --fix (then commit deliberately, per ADR D32)"
```

**Tests:** `uvx --from actionlint-py actionlint` and `uvx zizmor==1.9.0 --persona pedantic --format plain .github/workflows` both exit 0 (zero findings caused by this change).

**Verify command:**

## 7. Out of scope

- Changing any other CI workflow jobs or their pass/fail semantics.
- Upgrading any Expo package beyond the four drifted ones (57.0.28 / 57.0.20 / 57.0.26 / 57.0.6).
- Touching the `build`, `ios-build.yml`, or `eas-build.yml` recipes/workflows.
- Dependabot configuration.
- Any Python, renderer, or API code.

## 8. Review focus

1. `justfile` `check-mobile` recipe: the env var is a shell-prefix assignment (not `export`), scoped to that one command.
2. `audit.yml` advisory step: `|| true` at the end of `expo install --check` is intentional (non-failing); step has `EXPO_NO_TELEMETRY=1` and `CI=1`; `pnpm install --frozen-lockfile` before running.
3. `apps/mobile/package.json`: all four bumped pins are exact (no `~`), consistent with the project's determinism policy.
4. ADR D32: "not a weakening" argument — the 20 remaining expo-doctor checks plus `expo export` still catch real scaffold errors.
5. `docs/11-implementation-plan.md`: T0.2b row lists `T0.4` as dependency (correct — requires mobile scaffold to exist).
