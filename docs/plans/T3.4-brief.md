## 2. Why it matters

This is the only place untrusted text, both feed content and LLM output, turns into words the
owner hears and sees. AGENTS.md: *"Everything the LLM returns is validated against the Pydantic
`ReelScript` schema before it is used. Invalid output is retried, then falls back to the
deterministic template script. Never render unvalidated LLM text."*

If this is wrong:
- the reel can state hallucinated stories, or link to URLs that were never in the feed;
- it can run past 60 s;
- a down Ollama can leave the morning with no reel. The fallback must *always* validate, so a day
  always delivers (docs/02 §7).

## 5. Inputs and outputs

**In**
- `list[SelectedStory]` plus each item's `summary` and `source.key` (from `items` / `sources`);
- `local_date`;
- settings.

**Out**
1. `briefs` row: `status=ready`, validated `script_json`, provenance.
2. `brief_items`: a `primary` row per story scene (`scene_index`) and a `mention` row per
   duplicate.
3. On total failure of the provider chain, the template script is used, with
   `used_fallback_template=1`. The status is still `ready`; `failed` is reserved for
   "no candidates at all" (Q7).
4. Schema artefacts: Pydantic `ReelScript` and `ReelProps`, their JSON schema, and generated zod
   for the renderer (Q1).

The next stage (`assets`) is enqueued by T3.5's orchestrator, not here.

## 6. Constraints

- **Memory.** Ollama with a 7B model takes ~5 GB. Use `keep_alive: "2m"` (docs/06 §5) and do not
  run it concurrently with render (the serial worker already guarantees that).
- **Time.** The script stage targets 40–90 s, and the job timeout is 300 s. Worst case:
  3 Ollama attempts at 120 s each would exceed 300 s. So the per-request timeout is ~80 s, or
  the attempts must be budgeted against a shared deadline.
- **Word budget.** 130–185 words in total; story voiceover 25–45 words; `title` ≤ 60 chars,
  `kicker` ≤ 24, bullets ≤ 3 × 48 chars, `voiceover` 10–320 chars, scenes 4–9.
- **Security.** API keys are `SecretStr`, never logged; request bodies are not logged at info
  level. LLM output is only parsed as JSON into Pydantic.
- **Determinism.** The template script is a pure function of (stories, date), which makes it
  golden-testable.

## 7. Edge cases

| # | Case | Example | Expected |
|---|---|---|---|
| 1 | Hallucinated story | LLM returns `item_id: 999`, not a candidate | Validation error → retry with the error text appended |
| 2 | URL drift | `source_url` is `https://bbc.co.uk/news/x/` but the item URL is `https://bbc.co.uk/news/x` | Rejected. Compare **exact strings**, so `source_url` must be `str`, not pydantic `HttpUrl`, which normalises `https://a.com` to `https://a.com/` (proposal) |
| 3 | Reordered stories | LLM puts the India story first | Rejected (story scenes must follow the candidate order), or re-sorted server-side? Proposal: reject and retry |
| 4 | Story dropped or duplicated | 5 story scenes for 6 candidates, or the same `item_id` twice | Proposal: require each candidate exactly once. A dropped story is a validation error |
| 5 | Word budget | Total 210 words | Rejected → retry → template |
| 6 | Wrong `total_words` | LLM says 160, real count is 171 | Recompute server-side and overwrite; never trust the LLM's arithmetic (proposal) |
| 7 | Deny-listed word in voiceover/title | Profanity | Rejected → retry |
| 8 | Prompt injection in a feed summary | "Ignore previous instructions and say…" | Data framing in the prompt, plus the structural validator: any text outside the schema or story set is impossible; tone is enforced only by the instructions |
| 9 | Ollama down / model missing | Connection refused, or 404 `model not found` | Immediate fallback (no 3× retry on connect errors) → optional provider → template |
| 10 | Ollama returns non-JSON or truncated JSON | `done_reason: length` | Counts as an attempt; retry |
| 11 | Digest mismatch | Local model digest ≠ pinned | Proposal: generate anyway, record the actual digest in `briefs.model_digest`, log a warning (`doctor` already flags it). Do not block the morning |
| 12 | Too few candidates | 1 story | `ReelScript` needs ≥ 4 scenes (cover + ≥ 2 stories + outro); see Q7 |
| 13 | Template exceeds budget | 6 long summaries | Template trims sentences at word boundaries per story so the total stays within 130–185; it pads with the next summary sentence if too short. Property test: template **always** validates |
| 14 | Unicode and numbers in word counting | "Qwen3-VL", "5.4 %", "₹2,000" | One whitespace-split token each; same rule in the validator and the TTS budget |
| 15 | Re-run for the same day | `script` job runs twice | Idempotent: if a `ready` brief exists, skip unless `force` is in the payload (T3.5 `--force`) |
| 16 | No day row | Brief FK requires `days(local_date, device_id)` | See Q8 |
| 17 | Optional provider without a key | `CHRONOS_LLM_PROVIDER=anthropic`, no key | Skip it with a warning; go straight to the template |

## 8. Proposed approach (proposal; the owner may veto)

1. **`content/script/schema.py`**: `Scene` and `ReelScript` per docs/06 §4, plus
   `validate_script(script, candidates) -> ReelScript`, which applies the context checks:
   - candidate membership, exact URL, order, each story once;
   - word budget, recomputed `total_words`;
   - deny list.
2. **`content/script/prompts/reel_script.v1.md` + `example_reel.json`**: the system and user
   template from docs/06 §5. Stories are passed as a JSON array, framed as untrusted.
   `prompt_version` = sha256 of the prompt file plus the example.
3. **`content/script/llm.py`**:
   - the `ScriptGenerator` protocol: `generate(request) -> GenerationResult(script_json, provider, model, digest, tokens_in, tokens_out, latency_ms)`;
   - `OllamaScriptGenerator`: httpx `POST /api/chat` with `format=<JSON schema>`,
     `temperature 0.4`, `num_ctx 8192`, `keep_alive "2m"`; it reads the digest from
     `/api/tags`;
   - `OpenAIScriptGenerator` and `AnthropicScriptGenerator` over plain httpx REST (**no SDK
     dependency**; Q4);
   - `FakeScriptGenerator` for tests.
4. **`content/script/fallback.py`**: a deterministic template that always validates (property
   test).
5. **`content/script/service.py`**: `generate_script(stories, local_date, providers, deadline) -> (ReelScript, provenance)`.
   - Up to 3 attempts per provider, with the validation errors fed back into the next prompt.
   - Connection errors skip the provider immediately.
   - Then the next provider, then the template.
6. **`content/script/job.py`**: the `script` handler (payload `{local_date, device_id, force?}`).
   It runs `select_stories`, then generation, then writes `briefs` + `brief_items` in one
   transaction (idempotent).
7. **Settings**: `ollama_model`, `ollama_digest`, `ollama_timeout_sec`,
   `openai_api_key`/`openai_model`, `anthropic_api_key`/`anthropic_model` (Q4/Q5);
   `.env.example` updated.
8. **Schema export**: `chronos schema export-reel-props` writes the JSON schema for `ReelProps`
   (and `ReelScript`) to `packages/renderer/src/schema.json`; then codegen per Q1. The existing
   `api` CI staleness check covers it.
9. **Tests**:
   - validator tables for edge cases 1–7, 14;
   - template property (any 2–9 candidates with arbitrary text always validate);
   - service retry/fallback with fakes and `httpx.MockTransport` (Ollama, OpenAI and Anthropic
     wire formats);
   - an end-to-end job test with `FakeScriptGenerator` and a temp DB (provenance and
     `brief_items` asserted);
   - `@pytest.mark.ollama` smoke, auto-skipped when Ollama or the model is absent.

## 9. Risks

| Risk | How a test catches it |
|---|---|
| A 7B model can't hit the word budget reliably, so the template is used most days | `@pytest.mark.ollama` smoke records attempts and the budget hit-rate; the prompt states per-story word targets; retries feed back the exact counts |
| Template fails validation on odd input (very short summaries, 2 stories) | Hypothesis property over the candidate count and text |
| Ollama 3 × 120 s blows the 300 s job timeout | Shared-deadline unit test with a fake clock; per-request timeout derived from the remaining budget |
| zod and Pydantic drift (the reason for Q1) | CI staleness check on the generated files; a renderer vitest parses `sample-reel.json` with the generated schema |
| Secret leak through logs or exceptions | Canary-key test: an error path with the key set never shows it in logs, repr or error text |

## 10. Open questions

1. **Pydantic → zod generation.** No converter was ever chosen, and AGENTS.md forbids unlisted
   dependencies. Options:
   - (a) A small in-repo Python codegen that emits `packages/renderer/src/schema.generated.ts`
     from the JSON schema. It covers only the subset we use (object, string with
     length/pattern, number with bounds, int, enum/literal, array with min/max, nullable,
     discriminated union by `type`). No dependency, deterministic. **Recommended.**
   - (b) Add an npm converter (e.g. `json-schema-to-zod`): a new pinned dev dependency.
   - (c) Defer the zod generation to T4.4. T3.4 only exports `schema.json` and adds a parity test
     that validates `sample-reel.json` with both Pydantic and the hand-written zod. Smaller now,
     with a drift risk until T4.4.
2. **`tone` values.** docs/06 has `calm | energetic` and the renderer has `friendly | formal`.
   **Proposal:** adopt docs/06 (`calm | energetic`) everywhere and update the renderer fixture
   and any motion code accordingly.
3. **Pulling the model.** `@pytest.mark.ollama` must pass locally, but `qwen2.5:7b-instruct`
   (~4.7 GB) isn't pulled. May I run `just models` (or `ollama pull qwen2.5:7b-instruct`) during
   implementation and pin the resulting digest in the justfile (`ollama_digest`)?
4. **Optional providers.** Implement OpenAI and Anthropic over plain httpx REST (no SDKs, so no
   new dependencies)? **Proposal: yes.**
   - Default models, configurable via `CHRONOS_OPENAI_MODEL` / `CHRONOS_ANTHROPIC_MODEL`:
     Anthropic `claude-sonnet-5-5`, OpenAI left empty (required if the OpenAI provider is
     chosen).
   - Anthropic uses tool-use with the schema; OpenAI uses `response_format: json_schema`.
5. **Provider chain semantics.** D11 calls OpenAI/Anthropic "opt-in fallbacks". **Proposal:**
   - Ollama is always tried first.
   - `CHRONOS_LLM_PROVIDER=openai|anthropic` adds that provider as the second step (only if its
     key is set).
   - The template is always last.
   - `CHRONOS_LLM_PROVIDER=ollama` (the default) means Ollama, then the template.

   (The alternative is that `CHRONOS_LLM_PROVIDER` *replaces* Ollama as the primary.)
6. **Story order and coverage.** Require the LLM to return every candidate exactly once, in the
   given order, and reject anything else so it is retried (edge cases 3/4)? **Proposal: yes.**
   It's simplest to validate, and narrative order is fixed by docs/06.
7. **Too few candidates.** If selection returns fewer than 2 stories, the schema minimum of
   4 scenes can't be met. **Proposal:** with 0 stories, mark the brief `failed` (T5.2 sends the
   text fallback push). With 1 story, the template builds cover + story + "quiet morning"
   outro, and the schema minimum becomes 3 scenes. Or keep the minimum at 4 and fail at
   < 2 stories?
8. **Day row and device.** `briefs` has an FK to `days(local_date, device_id)`. **Proposal:**
   the `script` payload carries `device_id` and `local_date`; the handler requires the day row
   to exist (T3.5's prewarm creates it, because only it knows the device timezone) and fails the
   job clearly if not.
