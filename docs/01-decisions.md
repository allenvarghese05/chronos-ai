# Architecture Decision Records

Each row is binding until a new ADR in `docs/decisions/` supersedes it. New decisions made during
tasks go in `docs/decisions/Dnn-slug.md` using the same table shape and the next free number.

| ID | Decision | Choice | Why | Revisit if |
|---|---|---|---|---|
| D01 | Platform | iOS only (iOS 17+). | Owner uses an iPhone. | Android user appears. |
| D02 | Mobile stack | Expo SDK (latest stable at T0.4), `expo-dev-client`, `expo prebuild`, local Xcode build on the laptop (EAS Build optional). | Custom Swift module and background modes are impossible in Expo Go. | — |
| D03 | Wake triggers | No Shortcuts automations, no BLE beacon, no HealthKit/Watch. Signals come only from what the app can read when iOS wakes it. | Owner wants the signal system built in software. | Owner buys a beacon/Watch (would be an *additional* signal, same engine). |
| D04 | Background wake mechanism | Server-sent **silent pushes** every 5 min during the window (primary), `BGAppRefreshTask` (opportunistic supplement), app foreground (definitive). | Only ways to run code on iOS without the user; silent push is the one the server controls. | iOS throttling proves too aggressive in practice (then tighten tick spacing or add Live Activity / location-based wakes). |
| D05 | Signal set | Time window, pedometer steps (10 min + since window start), motion-activity walking seconds and confidence, device unlocked (`isProtectedDataAvailable`), charger disconnect transition, app foregrounded. | All readable in a 30 s background wake; combined they separate "up and moving" from "checked phone in bed". | Tuning data shows a signal is useless or a new one is available. |
| D06 | Scoring | Weighted additive score with per-signal caps, a 2-tick confirmation rule and a single-tick "strong" threshold; rules in `config/wake_rules.yaml` with a DB override; every evaluation stored. | Explainable and tunable; avoids a single noisy signal confirming the day. | Owner wants a learned model (would consume the same stored evaluations). |
| D07 | Window | Weekdays 06:00–11:00, weekends 08:00–14:00, phone's IANA timezone; fallback delivery at window end. | Owner's answer. | Travel/holiday schedules (config supports per-weekday overrides and holidays list). |
| D08 | One reel per day | Exactly one reel per local date; later triggers are no-ops. | Owner's answer; keeps the pipeline simple. | Owner wants per-story reels (M6 stretch). |
| D09 | Render mode | **Eager**: pipeline runs at window start − 30 min so the reel is ready; the wake trigger only delivers. `render_mode: on_trigger` kept as config for freshness experiments. | Push must arrive within seconds of waking; render takes minutes. | Owner prefers freshest-possible content over latency. |
| D10 | Backend | Python 3.12, FastAPI, SQLModel/SQLAlchemy 2, Alembic, SQLite (WAL), one process for API + an in-process worker/scheduler (APScheduler) with a SQLite `jobs` table; no Redis/Celery. | Single user, single laptop; fewer moving parts to supervise. | A second machine or user appears. |
| D11 | LLM | Ollama (default model `qwen2.5:7b-instruct`, pinned by digest) with JSON-schema constrained output; `CHRONOS_LLM_PROVIDER=openai|anthropic` as opt-in fallbacks; deterministic template script as last resort. | Zero cost, offline, 16 GB fits a 7B model. | Script quality is not good enough. |
| D12 | TTS | Kokoro-82M via `kokoro-onnx` (CPU/CoreML), voice pinned; `edge-tts` as network fallback. | Owner's answer; best free quality. | — |
| D13 | Captions | `whisper.cpp` (`whisper-cli`, model `ggml-small.en`) producing word-level timestamps from the TTS audio; Python aligns words to script scenes. | Owner's answer; Metal-accelerated on M1. | Kokoro exposes reliable phoneme timings (then skip ASR). |
| D14 | Renderer | Remotion (React, TypeScript) invoked by Python through `npx remotion render` with `--props` JSON; ffmpeg only for probing/verification and audio normalisation. | Best visuals; owner's answer. | Remotion licence terms change for the owner's use. |
| D15 | Push | Expo Push Service (APNs underneath) for both silent and visible notifications; no Firebase. | Fewer native SDKs, free, works with dev-client. | Expo push reliability issues (then direct APNs with a `.p8` key). |
| D16 | Network | Phone ↔ laptop over the home LAN. API binds to the LAN IP, HTTPS with a locally generated CA (mkcert) whose root is installed on the phone; device bearer token on every call. | Same Wi-Fi per owner; HTTPS keeps the token and media private even on LAN. | Owner wants access away from home (then Tailscale, same code). |
| D17 | Media delivery | MP4 served by the API at a signed, expiring URL; unsaved reels deleted after 24 h; saved reels kept until deleted by the owner. Cloud sync (R2/Supabase) is a later optional task. | Owner's answers. | — |
| D18 | Repo | Monorepo `apps/mobile`, `services/api`, `packages/renderer`; `just` as the single task runner; CI jobs run the exact `just check-*` commands. | Proven in typist-ml; one `just check` before push. | — |
| D19 | CI/CD | GitHub Actions with SHA-pinned actions and `permissions: contents: read`; checks `api`, `mobile`, `renderer`, `secrets` (required once a ruleset is possible); weekly audit, gitleaks, zizmor (CodeQL/dependency review need Advanced Security, unavailable on this private repo); **pull-based CD** on the laptop (launchd job fast-forwards `main` and restarts services). | No self-hosted runner exposed to GitHub; laptop only pulls signed-off `main`. | — |
| D20 | Branch protection | Ruleset on `main` (PR required, required checks, conversation resolution, no force-push/deletion, no bypass actors) **as soon as the plan allows it**; until then (private free-plan repo, 2026-10-06) the controls are squash-only merges, auto-delete branches, CI on every PR and the agents' never-push-to-main rule. | Mirrors typist-ml; agents can open but never merge. | Repo goes public or GitHub Pro. |
| D21 | Agents | Four project subagents in `.pi/agents/`: understander (cheap), implementer (strong), reviewer (strongest), pusher (cheap). Prompts `/understand`, `/implement`, `/review`, `/push`, `/task`. Pusher may push and `gh pr create`, never merge/approve. | Owner's answer. | — |
| D22 | Security scanning | Local: `just security` = semgrep (`p/security-audit`, `p/python`, `p/typescript`, pinned CLI), bandit, pip-audit, pnpm audit, gitleaks. CI: semgrep + bandit + gitleaks in the required-check jobs; zizmor and the weekly audit advisory (no CodeQL: needs Advanced Security). No third-party upload SaaS. | Same posture as typist-ml D22, extended with secret and workflow scanning. | — |
| D23 | Secrets | `.env` files gitignored; `services/api/.env.example` documents every variable; CI uses no secrets except `EXPO_TOKEN` in the manual EAS workflow; device tokens stored hashed (SHA-256) in SQLite; mkcert key file mode 600. | — | — |
| D24 | Privacy | Telemetry stores only the fields in `docs/04-data-model.md` (no location, no Wi-Fi identifiers, no contacts). 30-day retention for telemetry/evaluations; purge job nightly. | Minimise what a stolen laptop reveals. | — |
| D25 | Timezone | Phone sends IANA tz on every event; server derives local date and window; "day" boundaries at 03:00 local to avoid midnight edge cases. | Deterministic and testable. | — |
| D26 | Content sources | Fixed list in `config/sources.yaml` (HF daily papers, arXiv cs.AI/CL/LG, HN, BBC World, CBS, Indian Express India + Tech, NDTV). Per-source quotas and weights; dedupe by canonical URL hash and title similarity. | Owner's list. | Owner edits the YAML. |
| D27 | Visuals | Source `og:image` thumbnails (hot-linked never; downloaded, resized, EXIF-stripped) plus optional Pexels b-roll (free API key, opt-in via env) and generated gradient/particle backgrounds when nothing is available. | Owner wants images and video; stays free. | — |
| D28 | Observability | `structlog` JSON logs to `data/logs/`, rotated; `/metrics` (Prometheus text) for job durations and tick counts; nightly Markdown report of the day's evaluations; `chronos doctor` CLI. | Enough to debug a flaky morning without external services. | — |
| D29 | Config | Pydantic Settings with `CHRONOS_` prefix; YAML for rules/sources; schema-validated on startup; `chronos config validate` in CI. | — | — |
| D30 | Model weights | Ollama models, Kokoro ONNX and whisper ggml files live under `data/models/` (gitignored) and are fetched by `just models` with pinned URLs and SHA-256 checks. | Reproducible, nothing in git. | — |
